## 3. 设计原则

1. **后端唯一权威**：前端额度仅用于提示，所有 Provider 调用前必须经过服务端额度守卫。
2. **先预留，后确认**：请求发出前原子预留；成功按实际量确认；失败或取消释放。
3. **并发不超卖**：使用 PostgreSQL 行锁和唯一键，不用“先查剩余、稍后再扣”的分离逻辑。
4. **失败不扣额度**：Provider 失败、内容审核拦截、网络取消和服务端异常释放预留。
5. **数据库不可用时不调用付费 Provider**：硬额度模式下失败关闭，返回 503，不允许绕过计费。
6. **文本优先降级**：AI 语音额度用完时仍允许文字回答；图片/视频额度用完时允许用户改发纯文本。
7. **不使用 Local Storage**：套餐、周期、预留、用量和剩余额度只来自 PostgreSQL API。
8. **供应商原始 usage 与产品额度分开**：Token/字符用于成本，回复次数/语音秒数/附件数用于套餐权益。

## 5. 复用 usage_events 的原子预留

不新建一套重复的额度表，扩展现有 `usage_events.status`：

```text
reserved   已预留，Provider 尚未完成
completed  已确认用量
released   失败或取消，已释放
```

新增方法：

```python
reserve_usage(user_id, request_id, metrics, ttl=10min)
confirm_usage(user_id, request_id, metric, actual_quantity, raw_usage)
release_usage(user_id, request_id, metrics)
get_remaining(user_id)
```

`reserve_usage` 在一个事务内：

1. `SELECT user_subscriptions ... FOR UPDATE`；
2. 确保订阅当前周期正确；
3. 汇总当前周期 `completed` 与10分钟内未过期的 `reserved`；
4. 校验本次需求是否超过限额；
5. 插入 `reserved` 事件；
6. 提交后才允许调用 Provider。

`request_id + metric` 唯一；客户端重试同一请求时返回已有预留结果，不能重复扣减。超过10分钟的孤儿预留不计入剩余量，并由清理任务改为 `released`。

## 6. 请求 ID 与错误协议

聊天、语音、TTS、多模态和截图导入请求统一携带客户端生成的 `request_id`。浏览器只在当前内存中持有，不写 Local Storage。

### 6.1 鉴权与额度归属安全

当前 `current_user_id()` 在没有HttpOnly Session时会接受客户端 `X-Weiguang-User-ID`。这会让脚本伪造用户ID、切换额度账本或绕过实际购买账号，是开启硬额度前必须封堵的安全旁路。

要求：

- 所有会调用LLM、TTS、声音复刻、视觉模型或创建收费任务的生产接口统一使用 `required_user_id`；
- 用户ID只从服务端验证过的HttpOnly Session取得，不接受前端Header指定额度归属；
- `X-Weiguang-User-ID` 只能在显式开发开关下用于本机迁移/诊断，生产默认关闭；
- 未登录、过期Cookie和伪造Header均在Provider调用前返回401；
- 前端传入的 `plan_code`、limit、used、remaining和价格一律忽略；
- 生产Cookie必须启用 `Secure + HttpOnly + SameSite`，状态变更接口校验可信Origin/CSRF边界；
- 安全测试必须断言伪造Header不能读取、预留或消耗其他用户额度。

额度不足返回：

```json
{
  "code": "quota_exceeded",
  "metric": "ai_reply",
  "used": 1000,
  "limit": 1000,
  "remaining": 0,
  "reset_at": "2026-09-28T..."
}
```

HTTP 状态使用 `402 Payment Required`；`429` 只用于频率限制，不能混作套餐额度不足。

前端按 `metric` 显示：

- AI 回答已用完；
- AI 语音已用完，本次仅返回文字；
- 图片/视频额度不足，请移除附件；
- 音色槽位已满；
- 截图导入批次已用完。

## 9. AI 语音额度

### 9.1 流式语音

继续以24kHz、16-bit、单声道PCM计算真实时长：

```text

```

每个句子调用TTS前预留估算秒数；完成后以PCM实际秒数确认，差额在同一事务中补扣或返还。剩余额度不足以合成下一句时停止TTS并发送：

```text

```

## 13. 续费周期与额度重置

当前同档兑换会直接延长 `user_subscriptions.period_end`，但用量汇总仍从原 `period_start` 计算。若直接开启硬额度，续费后的第二个30天不会获得新额度，这是必须先修复的阻断项。

目标模型：

```text
user_subscriptions
  当前正在生效的30天额度周期

subscription_grants
  当前和未来排队的30天访问授权
```

同档续费时：

- 当前周期仍保持原 `period_start / period_end`；
- 新授权写入下一周期，例如 2026-09-28 → 2026-10-28；
- 个人中心同时展示“本期额度重置日”和“已续费至”；
- 到达周期边界时，由请求前 `ensure_current_cycle()` 原子切换到下一授权；
- 新周期的用量查询从新的 `period_start` 开始，额度自然归零；
- 定时任务只作提前修复，请求前切换是最终一致性保障。

当前账号再次兑换Plus后，访问权可续至约2026-10-28，但当前1000次/180分钟额度仍应在2026-09-28重置，而不是合并成一个60天周期。
