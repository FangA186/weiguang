## 1. 背景与问题定位

### 1.1 问题一：聊天历史图片/视频加载 403 Forbidden (`0002-00000069`)
- **现象**：在聊天页面 (`localhost:5173/chat`) 刷新或加载历史记录时，历史消息中包含的图片附件请求失败，控制台与网络面板报 `403 Forbidden`，阿里云 OSS 响应头返回 `X-Oss-Ec: 0002-00000069`，响应为 `Request has expired`。
- **根因**：
  1. 用户在发送图片/视频消息时，后端通过 `presign_media_upload` 生成了临时的短时下载链接（有效期通常为 900 秒 = 15 分钟），并将其直接序列化保存至 PostgreSQL `chat_messages.attachments` JSON 字段中。
  2. 当用户稍后刷新页面或次日进入聊天时，`GET /api/chat-history` 直接将数据库中已过期的签名 URL 返回给前端。
  3. 前端 `<img :src="att.download_url || att.url">` 访问过期的 URL，OSS 判定签名时间戳已过期（截图显示签名到期时间为 `Expires=1788363704`，距当前已过去近 20 小时），返回 HTTP 403。
- **解决方案**：
  1. **后端动态刷新签名**：在 `GET /api/chat-history` 以及管理员审查接口 `GET /api/admin/conversations/{id}/messages` 中，对返回的每一条消息中的 `attachments` 遍历；如果附件包含 `object_key`，通过 `OSSProvider.presign_object_download(object_key)` 动态重新生成有效的临时下载签名 URL。
  2. **前端健壮性兜底**：在 `ChatView.vue` 中对媒体图片加载失败增加兜底显示与容错处理。

---

### 1.2 问题二：Ex-Skill 五层人格系统用户体验改造 —— OCR 后自动形成人设，支持工坊手动微调
- **现状与痛点**：
  - 用户导入聊天截图并通过 OCR 识别出消息后，想要提炼人设，却被弹窗引导到一个多步骤向导中，要求手动输入“角色姓名”、“MBTI”、“依恋类型”、“性格标签”、“主观备忘”等。
  - 用户体验割裂：既然 AI 视觉已经把多张聊天截图中的发言、语气、词汇和互动全量扫描出来了，系统就应该**全自动**从这些真实对话素材中直接推导角色人设与记忆，而不是把填写问卷的负担推给用户。
- **改造目标**：
  1. **零门槛全自动提炼 (Zero-Prompt Auto Distillation)**：
     - 用户在 OCR 识别完成后，一键点击“✨ 自动生成角色人设”；
     - 后端根据聊天截图内容，自动识别非用户侧的发言人身份/昵称（或由 LLM 推断人物角色称呼），直接调度 Ex-Skill 两阶段分析器（Stage 1: 5层 Persona 架构，Stage 2: 共同记忆库）；
     - 自动推断出 MBTI、依恋类型、口头禅、标点习惯、情绪模式、禁忌话题与专属回忆，无需用户手动填写任何表单。
  2. **自动激活并无缝跳转角色工坊微调**：
     - 提炼完成后，自动将新生成的角色设为当前激活角色；
     - 自动弹出**角色工坊 (`PersonaWorkshopDialog.vue`)**，以顶部温馨提示横幅告知用户：“已根据聊天记录为您自动提炼角色【XX】！如果对某些细节不满意，可随时在下方手动调整”；
     - 用户可直接在工坊中自由修改 L0 硬规则、L1 画像、L2 口癖/标点、L3 情绪、L4 冲突以及共同回忆，真正实现“AI 自动提炼底模 + 用户按需微调”的高效闭环。
  3. **简化向导组件 (`DistillWizardDialog.vue`)**：
     - 将原本强制手动输入的表单项改为完全可选的高级补充选项，默认一键选择素材即开始蒸馏。

## 2. 实施技术方案

### 2.1 后端改动
1. **`backend/app.py`**：
   - 增加辅助函数 `_enrich_messages_attachments(messages: list[dict[str, Any]]) -> None`，使用 `OSSProvider(settings).presign_object_download(att["object_key"])` 刷新过期 URL；
   - 在 `GET /api/chat-history` 返回前调用该函数；
   - 在 `GET /api/admin/conversations/{conversation_id}/messages` 返回前调用该函数；
   - 新增接口 `POST /api/personas/distill-from-import`：
     - 入参：`import_id: int`，`name: Optional[str] = None`；
     - 逻辑：读取批次消息，提取对方昵称，创建 Persona 并调用 `PersonaDistiller`，完成后设置为 active 并返回。
2. **`backend/persona_distiller.py`**：
   - 允许 `name` 未指定时，提示 LLM 从对话内容中自主推断人物角色名称与称呼（如“根据聊天记录推断此角色的合适称谓”）；
   - 优化 Prompt 输入，强化从纯对话记录中推断 MBTI 与依恋类型的推理逻辑。

### 2.2 前端改动
1. **`frontend/src/components/ChatImportDialog.vue`**：
   - 在 OCR 完成后的审查界面以及导入成功界面，强化“✨ 自动生成角色人设”按钮；
   - 点击后展示原地轻量进度状态（“正在基于聊天记录分析性格习惯与回忆...”）；
   - 调用 `personaStore.distillFromImport(batchId)`，完成后自动关闭导入弹窗，并自动打开 `PersonaWorkshopDialog`。
2. **`frontend/src/stores/personaStore.ts`**：
   - 新增 `distillFromImport(importId: number, name?: string)` 方法；
   - 提炼成功后刷新 personas 列表，切换到新角色，设置编辑目标为该角色，并打开工坊弹窗。
3. **`frontend/src/components/PersonaWorkshopDialog.vue`**：
   - 增加生成成功的提示横幅（“🎉 已根据聊天记录自动生成专属角色！如对参数不满意，可随时在下方手动调整。”）；
   - 确保所有字段均与新生成的 Persona 数据无缝双向绑定。
4. **`frontend/src/views/ChatView.vue`**：
   - 图片预览与缩略图增加 `@error` 兜底，防止网络偶发闪断时显示丑陋裂图。
