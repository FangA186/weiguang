# [已完成] 微光浏览器转写保留与套餐前端改造方案

> **状态**：已完成 (Completed)
> **创建时间**：2026-08-27
> **完成时间**：2026-08-27
> **关联方案**：`plan/2026-08-27_产品套餐与商业化计费方案.md`
> **当前决策**：第一阶段不接入 Qwen、MiMo 或其他独立 ASR；继续使用浏览器 `SpeechRecognition`，只改造套餐展示、个人中心、用量口径和前后端数据边界

## 1. 结论

本轮不开发服务端 ASR，不上传麦克风原始音频，不增加 `ASRProvider`、ASR 环境变量、音频转写接口或 ASR 计费表。

当前语音链路保持：

```text
浏览器麦克风
  → SpeechRecognition / webkitSpeechRecognition
  → 浏览器返回一轮文本
  → POST /api/chat-and-tts/stream
  → Qwen3.5-Flash 文本回答
  → Qwen-Audio-3.0-TTS-Flash 克隆音色合成
  → SSE PCM 分片播放
```

第一阶段只交付：

1. `/pricing` 公开套餐页；
2. 个人中心的当前套餐与多维用量概览；
3. 导航、注册提示和额度耗尽提示的产品化改造；
4. 服务端可核对的影子用量汇总；
5. 浏览器不支持语音识别时的明确降级。

第一阶段不交付支付、自动续费、退款、年付、加量包购买或真实套餐切换。Plus/Pro 按钮先显示“即将开放”，不能伪造购买成功。

## 2. 为什么先不接独立 ASR

- 当前聊天页和全屏语音页已经使用浏览器识别并把文本送入现有 API，继续沿用改动最小；
- 首批约 50 名邀请用户可以先限定推荐浏览器，优先验证声音复刻、语音陪伴和套餐转化；
- 微光服务端不接收麦克风原始录音，可以少维护一条上传、转码、重试、存储、删除和计费链路；
- 现阶段真正影响付费落地的是 `999999` 假额度、缺少套餐页和用量展示，而不是缺少第二套转写服务。

浏览器识别仍有边界：`SpeechRecognition` 不是所有浏览器都稳定支持；Chrome 等浏览器可能把音频交给浏览器厂商的在线识别服务处理，并不等于纯本地离线识别。因此页面只能承诺“微光服务端不接收麦克风原始录音”，不能宣传“音频绝不离开设备”。

官方参考：

- [MDN SpeechRecognition](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)
- [MDN Using the Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API/Using_the_Web_Speech_API)

## 3. 范围边界

### 3.1 本轮包含

- 公开套餐页与移动端适配；
- 免费、Plus、Pro 权益展示；
- 当前套餐、AI 回复、AI 语音、图片、视频和音色槽位展示；
- 浏览器识别支持检测与文字输入降级；
- 服务端记录 Qwen LLM、TTS、多模态和声音复刻用量；
- 影子配额：计算但暂不阻断真实请求；
- 前端移除面向用户的“百炼 API”等供应商文案。

### 3.2 本轮不包含

- Qwen ASR、MiMo ASR、FunASR 或其他转写 Provider；
- `MediaRecorder` 音频上传和音频文件转写；
- ASR 输入分钟、ASR 费用和 ASR 配额；
- 支付 SDK、支付 Provider 抽象、订单回调和退款；
- Creator 套餐、年付套餐和优惠券；
- 新 UI 框架、图标库、图表库或状态管理依赖；
- 把规划中的长期记忆包装成已经可售的权益。

## 4. 用户口径调整

不接独立 ASR 后，套餐中的“语音分钟”改名为 **AI 语音时长**，只统计 Qwen TTS 实际生成的 AI 音频，不统计用户在浏览器内说话的时长。

| 指标 | 定义 | 首期是否阻断 |
|---|---|---|
| AI 回复 | 成功生成一次完整 AI 回答计 1 次 | 否，先影子统计 |
| AI 语音 | TTS 实际合成的音频时长 | 否，先影子统计 |
| 图片 | 成功提交模型理解的图片张数 | 否，先影子统计 |
| 视频 | 成功提交模型理解的视频条数 | 否，先影子统计 |
| 截图导入 | 成功创建的导入批次 | 否，先影子统计 |
| 活跃音色 | 当前可选择使用的克隆音色数 | 现有音色规则继续生效 |

浏览器识别失败不扣额度；浏览器完成转写但后端 LLM/TTS 失败也不计入成功用量。

## 11. 后端最小改造

### 11.1 API

第一阶段只新增一个只读接口：

```text
GET /api/billing/summary
```

不新增 checkout、cancel、webhook 或支付 Provider。

### 11.2 用量事件

后台只记录已经存在的供应商调用和业务动作：

```text
ai_reply_completed
tts_audio_generated
image_submitted
video_submitted
chat_import_created
voice_slot_activated
```

不记录 `asr_seconds`、麦克风音频或 ASR Provider。浏览器转写文本进入聊天消息后，按普通用户文本处理。

### 11.3 AI 语音时长

流式 PCM 为 24kHz、16-bit、单声道时，服务端可按已验证的音频字节数累计：

```text
audio_seconds = decoded_pcm_bytes / (24000 × 2)
```

服务端在 SSE `stream.done` 前汇总本轮秒数并写入用量事件。非流式按需朗读若暂时只有 URL，则先记录 TTS 计费字符和一次调用，不伪造精确分钟；统一分钟计量必须等该路径也能获得真实音频长度后再开启硬阻断。

### 11.4 数据落盘

首期只需要一个追加式 `usage_events` 表和按用户聚合查询，不创建完整订单、订阅、优惠券和退款表：

```text
usage_events
  id, user_id, request_id, metric, quantity,
  status, provider, model, occurred_at
```

`request_id + metric` 唯一，避免重试重复计量。根据当前 `AGENTS.md`，数据库迁移入口仍存在 `internal/auth/migrations/` 与现有 FastAPI `backend/migrations/` 的冲突；开始编码前必须先确认统一入口，不能在两个目录重复维护同一迁移。
