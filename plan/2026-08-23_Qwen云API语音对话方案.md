# [未完成] 阿里云百炼国内 Qwen3 TTS API 语音对话并发与成本方案

> **状态**：未完成 (Pending)
> **创建时间**：2026-08-23
> **适用范围**：首期最多 50 个注册用户，容量目标为 25 个同时处于一轮语音对话中的用户。
> **当前决策（2026-08-23）**：采用纯云 API 方案；LLM 与 TTS 接入阿里云百炼华北 2（北京），默认 LLM 采用 `qwen3.5-flash`，默认 TTS 采用 `qwen-audio-3.0-tts-flash`；ASR 仍采用既定 Xiaomi MiMo 方案。

## 0. 当前有效方案

```text
用户文本/麦克风/图片/音频/视频
   ↓
   应用网关（鉴权、上传校验、对象存储、限流）
   ├─ 麦克风语音 → MiMo-V2.5-ASR → 文本
   ├─ 文本/图片/视频 → 阿里云百炼 qwen3.5-flash
   └─ 音频附件 → qwen3.5-omni-flash（按需路由）
   ↓
阿里云百炼 qwen3.5-flash 生成文本回答
   ↓
阿里云百炼 qwen-audio-3.0-tts-flash（用户克隆音色）
   ↓
WebSocket 音频流 → 网页播放
```

当前默认 TTS 为阿里云百炼 `qwen-audio-3.0-tts-flash`；若实时接口或配额不满足要求，降级为百炼 `qwen3-tts-vc-2026-01-22` HTTP 分句合成。

普通文本、图片和视频理解由 `qwen3.5-flash` 负责；只有需要直接理解音频附件时才路由到 `qwen3.5-omni-flash`。Qwen3.5-Flash 不接收音频，因此麦克风语音必须先由 MiMo ASR 转成文本。Qwen3 TTS 只接收最终文本并输出语音，不负责理解多模态内容。应用侧仍需实现文件上传、类型/大小校验、对象存储或 Base64 转换，以及多模态消息 adapter。

## 1. 结论

当前采用“MiMo ASR + 阿里云百炼 Qwen3.5-Flash LLM + 阿里云百炼 Qwen TTS API”的纯 API 方案。这里的“语音对话”仍按轮次实现：浏览器录音 → ASR → LLM → 百炼 Qwen-Audio-TTS → 浏览器流式播放；首期不承诺全双工打断式实时流。

每个用户的授权参考音频由后端提交到 Qwen 声音克隆接口，保存返回的 voice 标识、目标模型、创建状态和授权记录。克隆 voice 与合成模型必须匹配，创建过程按幂等后台任务实现。

Qwen3-TTS-Realtime 官方页面给出的典型请求频率上限为 180 RPM，但 RPM 不等同于 WebSocket 同时连接数。25 路目标仍需用当前账号在目标地域压测，并在网关设置并发信号量、短队列、超时和 HTTP 降级。

## 2. 推荐拓扑

```text
浏览器文本/录音/多模态附件
   │
   ├─ ASR API（Xiaomi MiMo-V2.5-ASR，服务端并发限额需确认）
   ├─ LLM API（阿里云百炼 Qwen3.5-Flash，文本、图片、视频理解）
   ├─ 音频附件路由（Qwen3.5-Omni-Flash，按需理解音频）
   ├─ TTS API（阿里云百炼 Qwen-Audio-TTS-Flash，WebSocket/HTTP）
   └─ PCM/MP3/Opus 音频流返回，网页顺序播放
```

后端保持 API Key，浏览器只拿业务会话令牌。每一轮使用 `request_id`，ASR、LLM、TTS 分别记录排队时间、首字节时间、生成时长和错误码。

## 3. 并发判断

| 链路 | 25 人目标判断 | 主要限制 | 建议 |
|---|---|---|---|
| LLM | 架构上可行；是否能直接放行取决于账号和具体模型配额 | 云端 LLM 按在途请求数和 RPM/TPM 限流，不应只看 HTTP 连接数 | 网关信号量设 25，预留 5 个容量；未确认配额前排队 |
| ASR | 接口能力满足方案，但不能默认承诺 25 路 | MiMo ASR 快速开始页未公开并发权益 | 在控制台确认并发；网关保留 25 路信号量和短队列 |
| Qwen3 TTS | 官方实时接口支持流式输出，25 路仍取决于账号和地域配额 | 180 RPM 不等于并发 WebSocket 数；还受单连接时长影响 | 网关并发信号量设 25，保留 HTTP VC 降级和短队列 |
| 声音克隆 | 采用 Qwen API 后台任务 | 克隆 voice 必须与目标 TTS 模型匹配；创建费和账号配额需确认 | 创建音色返回内部 `voice_id`，幂等、可重试；前端轮询状态 |

## 4. API 成本口径

- Xiaomi MiMo-V2.5-ASR 官方首页当前显示 $0.074/音频小时；成本按用户实际上传音频时长计，不按并发计，最终以 MiMo 控制台账单为准。
建议账单按“对话轮次 + 音频分钟 + 音色创建次数”记录，而不是提供无限量套餐。内部成本公式：

`单轮成本 = ASR 分钟费 + LLM 输入/输出 token 费 + TTS 字符费 + 存储/带宽 + 重试损耗`

## 6. 上线前验收门槛

1. 用 80/150/300 汉字三档文本，分别压测 1、5、10、15、25 个并发。
2. 记录 P50/P95：ASR 完成、LLM 首 token、TTS 首音频、整轮可播放时间；目标先定为 P95 一轮 ≤ 8–12 秒。
3. 证明 25 路 ASR 配额或配置网关排队策略；不能通过多账号规避平台限流。
4. 进行 API 超时、重试、重复播放、连接断开和用户取消任务测试。
5. 根据真实“每用户每天轮数、每轮音频时长、LLM 上下文长度”重新计算套餐毛利，连续观察至少 7 天后再决定是否扩容网关、Redis 或数据库。

## 9. 2026-08-23 方案调整：MiMo ASR 与 Qwen TTS

### 9.1 ASR 改用 Xiaomi MiMo

采用 `mimo-v2.5-asr`。官方文档支持 WAV/MP3，以 Base64 或 Data URL 传入，Base64 后大小上限为 10MB；同时提供非流式和流式响应。该接口是 OpenAI SDK 兼容的 HTTP Chat Completions 调用，不应直接当作实时麦克风 WebSocket 流式识别协议；当前产品仍按“用户说完一轮后提交音频”实现。

MiMo 官方首页当前显示 MiMo-V2.5-ASR 为 `$0.074 / audio hour`，折算约 `$0.00123 / audio minute`；按 2026-08-23 约 6.72 的美元兑人民币粗算，约 0.0083 元/分钟。最终以 MiMo 控制台账单和 Token Plan 为准。

MiMo ASR 快速开始页没有公开 25 路并发保障，不能从低价格推导并发能力。上线前需在控制台确认限额，并做 1/5/10/25 路压测；网关仍需保留 ASR 信号量和短队列。

## 10. LLM 选型补充

### 10.1 云端 LLM 成本判断

首期 50 用户、每月约 30,000 轮的规模下，云端 LLM 更划算。国内华北2（北京）官方价格为输入 0.2 元/M、输出 2 元/M（单次输入不超过 128K）；按每轮 2,000 输入 tokens + 150 输出 tokens 估算，LLM 月成本约 21 元，未计图片/视频 token、重试和超长上下文。

### 10.2 推荐模型

首选 `qwen3.5-flash` 非思考模式：国内北京地域支持文本、图片和视频输入，输出文本，并支持 Function Calling、结构化输出、联网搜索、上下文缓存和批量推理；最大上下文约 1M tokens。北京当前模型别名公开限额为 RPM 30,000、TPM 10,000,000，足以覆盖 25 路目标，但仍需以账号控制台实际配额为准。音频由 MiMo ASR 负责转写；音频附件再路由到 `qwen3.5-omni-flash`。

北京 OpenAI 兼容 API 推荐使用业务空间专属地址：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`；旧的 `https://dashscope.aliyuncs.com/compatible-mode/v1` 仍可用。模型名使用 `qwen3.5-flash`，如需固定版本可使用 `qwen3.5-flash-2026-02-23`，但快照限额低于当前别名。

`mimo-v2.5` 保留为全模态音频理解的备用模型，不再作为默认 LLM。复杂问题是否启用思考模式，需单独压测首 token 延迟和回答长度，不能默认打开。

备用模型可接 `deepseek-v4-flash` 非思考模式。DeepSeek 官方价格为缓存命中输入 $0.0028/M、未命中输入 $0.14/M、输出 $0.28/M，并公开 2,500 路并发上限；适合作为高并发或 MiMo 配额不足时的备用，但需要单独验证中文角色感、内容安全和服务区域。

| 成本项 | 低用量/低价口径 | 基准估算 | 高用量/保守口径 |

## 12. 产品定价建议（基于 50 用户与纯 API 成本）

### 12.1 定价结论

按当前成本表（约 1,300–3,100 元/月）和最多 50 个用户，首期不建议做“无限语音”。推荐用“月度会员 + 语音额度 + 并发优先级”的组合，套餐按“轮次或语音分钟先到者”为准，避免少数重度用户耗尽 API 配额。

建议首发三档：

| 套餐 | 月价 | 建议额度 | 声音克隆 | 并发/服务 | 适用人群 |
|---|---:|---|---|---|---|
| 免费体验 | 0 元 | 30 轮或 10 分钟输出语音 | 1 次预览/试用 | 低优先级，1 个任务 | 获客与体验产品效果 |
| 基础版 | 49.9 元 | 300 轮或 45 分钟输出语音 | 1 个音色 | 标准队列，1 个任务 | 低频陪伴、日常问答 |
| Pro 版 | 89.9 元 | 1,000 轮或 120 分钟输出语音 | 3 个音色 | 优先队列，2 个任务 | 主力付费用户 |
| Creator 版 | 169.9 元 | 3,000 轮或 360 分钟输出语音 | 5 个音色 | 最高优先级，4 个任务 | 重度用户、内容创作者 |

额度建议按“助手输出音频分钟”计量，同时设置单轮最大输出长度（例如 120–180 个汉字）。轮次只作为用户易理解的展示口径；实际扣费以输出分钟为准，用户输入 ASR 不单独向用户计费。超出后可按 0.15 元/分钟或 0.10 元/轮购买加量包；额外声音克隆可收取 3–6 元/个，或直接作为 Pro/Creator 的权益。

这个价格带与市场锚点基本一致：国内同类陪伴产品风栖 AI 官网展示免费档、39 元/月档和 99 元/月档，其中 39 元档包含 120 分钟自然语音和 30 分钟实时通话，99 元档包含 360 分钟自然语音和 120 分钟实时通话（具体权益以其官网当前页面为准）。全球产品 Character.AI 的官方订阅为 9.99 美元/月，但其用户规模、模型和基础设施与当前项目不可直接类比。因此，49.9/89.9/169.9 更适合作为本项目的起始价格，而不是照搬竞品的“无限”宣传。

### 12.2 盈亏平衡

以下只计算覆盖技术成本，不含税费、支付手续费、客服、获客和研发工资：

| 月价 | 覆盖 1,600 元所需付费用户 | 覆盖 3,100 元所需付费用户 | 对 50 用户池的要求 |
|---:|---:|---:|---|
| 49.9 元 | 33 人 | 63 人 | 50 人全付也只能覆盖低成本场景 |
| 89.9 元 | 18 人 | 35 人 | 需要约 36%–70% 的用户付费 |
| 169.9 元 | 10 人 | 19 人 | 需要约 20%–38% 的用户付费 |

所以，如果用户总量确实封顶 50 人，建议把 Pro 作为主推档，并让 Pro/Creator 贡献至少 3,000–4,000 元/月；只靠 49.9 元基础版仍然很难覆盖 API 和基础设施成本。若预计只有 10–20 人付费，应提高 Creator 占比或增加按量加购。

### 12.3 上线策略与限制

1. 首发可给前 20 个用户一个月 39.9 元体验价，但不要把 39.9 元作为长期公开价；收集真实的日均轮次、输出分钟、峰值并发后再调整额度。
2. “25 路并发”是系统峰值容量，不是每个套餐的同时使用承诺。建议基础版 1 路、Pro 2 路、Creator 4 路，其余请求排队；队列长度、超时和降级策略要在产品页写清楚。
3. 可提供年付 10%–12% 折扣，例如 Pro 969 元/年、Creator 1,839 元/年，但在使用数据稳定前不宜折扣过深。
4. 运营看板至少记录每用户输出分钟、ASR 分钟、LLM tokens、API 队列等待时间和失败重试次数。若 P95 用户月用量超过套餐额度的 70%，优先调整额度或加量包，再扩容网关或托管服务。

### 12.4 推荐的首期公开价格

若现在就需要一个简单可执行的版本，采用：**免费体验 + 基础版 49.9 元/月 + Pro 89.9 元/月 + Creator 169.9 元/月**。产品宣传重点放在“授权声音克隆、可持续对话、中文语音质量和隐私”，不要承诺无限轮次或无限并发。

### 13.3 适合当前项目的选择

当前优先把 `qwen-audio-3.0-tts-flash` 作为 TTS 候选进行验证：它与 VC-Realtime 价格相同，但支持声音复刻、HTTP/WebSocket 和指令控制，理论上更适合产品的语速、情绪和风格需求。若接受“说完一轮再返回音频”，`qwen3-tts-vc-2026-01-22` 更便宜（¥0.8/万字符），可作为低成本非实时版本。`qwen3-tts-vc-realtime` 作为实时克隆音色回退。CosyVoice-v3.5-flash 价格同为 ¥0.8，但当前应先验证克隆相似度、中文表现和 SDK 兼容性。所有候选都需要确认账号并发连接、地区路由、声音创建费、数据留存和商业授权。

#### 最终 TTS 选型排序

1. **主选：`qwen-audio-3.0-tts-flash`**。北京价格 ¥1/万计费字符，支持声音复刻、声音设计、情绪/语速/风格指令，并同时提供 HTTP 与 WebSocket，作为当前产品默认 TTS。
2. **低成本非实时：`qwen3-tts-vc-2026-01-22`**。北京价格 ¥0.8/万计费字符，支持声音克隆但不支持显式情绪指令，适用于“ASR → LLM → 完整 TTS → 浏览器播放”的轮次式对话。
3. **实时备选：`cosyvoice-v3.5-flash`**。北京价格 ¥0.8/万计费字符，支持声音克隆和指令控制；在首包延迟、克隆相似度、中文表现及并发稳定性通过压测后，作为实时链路备选。

实施时先对 1、2、3 使用同一段授权音频和同一批测试文本进行 A/B 测试，再根据克隆相似度、情绪控制、首包延迟、错误率和 25 路并发结果确定最终生产模型。未通过测试前不承诺固定模型名或无限并发。

如果只做“用户说完一轮，再生成完整回复”，可选 `qwen3-tts-vc` HTTP，价格更低，链路更简单，但首包延迟通常不如实时版。

Qwen 官方页面列出的 180 RPM 只能说明请求频率上限，不能等同于 180 个并发 WebSocket 会话。25 路目标仍需进行 1/5/10/25 路压测，并为网关配置信号量、超时和降级队列。

### 13.4 克隆音色的语速、情绪和音色控制边界

当前选定的 `qwen3-tts-vc-realtime-2026-01-15` 支持自定义克隆 voice 和实时流式输出，但官方参数表将以下控制标记为不支持：

- `speech_rate`：不能通过参数直接调速；
- `volume`：不能通过 TTS 参数直接调音量；
- `pitch_rate`：不能通过参数直接调音高；
- `instructions` / `optimize_instructions`：VC-Realtime 不支持自然语言情绪/风格指令。

因此，VC-Realtime 的情绪、停顿、语气和韵律主要由模型根据文本语义、标点和上下文自动生成，不能承诺传入 `emotion=happy` 就固定输出开心语气。应用层可以通过文本改写、标点和分句影响表现，但属于软控制。

如果产品必须支持显式情绪或语速控制，有两条备选路线：

1. 保留 VC-Realtime，接收 PCM 后在服务端做变速/变调等音频后处理；速度和音高可控，但需要额外 CPU、延迟和音质回归测试，情绪仍不是参数化控制。
2. 评估 `qwen-audio-3.0-tts-flash` 或 `qwen-audio-3.0-tts-plus`：官方模型表同时标注“自定义音色”和“Instruction control”，可用自然语言控制速度、情绪和风格；但需单独验证克隆相似度、实时首包延迟和与当前 WebSocket 链路的兼容性。

不要直接切换到 `qwen3-tts-instruct-flash-realtime` 来解决情绪控制，因为该系列支持 instructions，但不支持用户克隆 voice。

### 15.3 成本和并发判断

Omni 的 RPM 60 是请求频率限制，不是 60 条 WebSocket 同时连接的承诺；25 用户并发必须按“连接数、每分钟轮次、音频时长、首包延迟”做压测。Qwen3.5-Omni-Flash 的 TPM 100K 也可能先于 RPM 成为瓶颈。

音频成本对时长非常敏感。按 Qwen Omni 文档的音频 token 换算口径估算，30,000 轮/月、每轮 30 秒用户音频约产生 11.25M 音频 token；仅按 Qwen3.5-Omni-Flash 国际区音频输入价 3 美元/M，输入音频约 33.75 美元/月，尚未计文本、输出音频和图片/视频。故 Omni 适合作为“多模态附件专用路由”，不适合无条件替代 MiMo ASR + 克隆 TTS 主链路。

### 15.4 落地顺序

1. 保持 `MiMo ASR → 阿里云百炼北京 qwen3.5-flash → 阿里云百炼 qwen-audio-3.0-tts-flash` 为首期默认方案。
2. 新增 `multimodal_router`：无附件走 Qwen3.5-Flash；图片/视频仍走 Qwen3.5-Flash；音频附件才走 `qwen3.5-omni-flash` 或 MiMo，统一只返回文本给克隆 TTS。
3. 单独压测 `qwen3-omni-flash-realtime`，只有在需要“单模型语音到语音”且能接受内置音色、60 RPM 和更高费用时才评估切换。
4. 记录每次请求的输入模态、音频秒数、输入/输出 token、模型、地区和账单金额，避免用文本 token 估算全模态成本。
