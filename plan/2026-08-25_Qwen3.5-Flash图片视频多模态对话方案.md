# [未完成] Qwen3.5-Flash 图片与视频多模态对话方案

> **状态**：未完成 (Pending)；代码实现已交付，视频端到端验收待补
> **创建时间**：2026-08-25
> **完成时间**：2026-08-25
> **适用范围**：微光当前 Vue 3 + FastAPI + 阿里云百炼 Qwen3.5-Flash 纯 API 架构
> **前置决策**：继续使用现有 `qwen3.5-flash`，不切换到 Qwen3.5-Omni；图片和视频只作为 LLM 输入，回答仍由文本流和现有 Qwen TTS 链路输出。

## 1. 目标

让用户可以在微光聊天页中：

- 上传一张或多张图片并提问；
- 上传视频并询问画面内容、动作、字幕或时间顺序；
- 在文本聊天中引用图片/视频上下文；
- 语音提问图片或视频，先转文字，再将文字和附件一起提交给 Qwen3.5-Flash，最后用克隆音色朗读文本答案；
- 在当前对话中保留附件引用，避免刷新后把无关或失效的临时 URL重新发送给模型。

官方模型信息确认 `qwen3.5-flash` 的输入模态包含 Text、Image、Video，输出模态为 Text。OpenAI-compatible Chat Completions 支持 `content` 数组，其中图片使用 `image_url`，视频文件使用 `video_url`。[官方模型说明](https://help.aliyun.com/zh/model-studio/qwen3-5-flash) [官方 Chat API 参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)

## 2. 明确边界

### 2.1 本阶段实现

- 图片：JPG、JPEG、PNG、WEBP；通过 OSS 私有 Bucket 临时签名 URL传递给 Qwen。
- 视频：MP4、MOV、WEBM 等常用格式；通过 OSS 临时签名 URL传递给 Qwen，并设置合理的 `fps`。
- 文本回答：继续使用 `qwen3.5-flash` 流式输出。
- 语音回答：继续使用现有 `/api/chat-and-tts/stream`，只把最终文本答案交给 Qwen TTS。
- 附件归属：附件记录绑定本地用户 ID和会话 ID。

### 2.2 本阶段不实现

- 不将图片或视频直接传给 TTS；TTS只处理最终文本。
- 不实现视频音轨理解、语音识别或音视频全模态输出；`qwen3.5-flash`本阶段只负责图像/视频视觉理解和文本回答。
- 不把附件永久公开；模型访问使用短期签名 URL或后端受控转发。
- 不自动把所有历史附件重新发送给模型；仅发送当前轮附件和被明确引用的历史附件。

## 3. 总体架构

```text
Vue ChatView
  ├─ 文本输入
  ├─ 图片/视频选择、预览、移除
  └─ 语音转写结果
       │
       ▼
FastAPI
  ├─ POST /api/uploads/presign-media
  ├─ PUT 临时 URL → OSS 私有 Bucket
  ├─ POST /api/chat/stream 或 /api/chat-and-tts/stream
  └─ 将结构化 messages 转交 Qwen3.5-Flash
       │
       ▼
阿里云百炼 qwen3.5-flash
  content: text + image_url/video_url
       │
       ▼
文本增量 → 页面
文本答案 → Qwen TTS → PCM 音频分片 → 浏览器播放
```

## 4. 消息结构

纯文本消息继续使用字符串；带附件的用户消息使用 OpenAI-compatible `content` 数组：

```json
{
  "role": "user",
  "content": [
    {
      "type": "text",
      "text": "请描述这张图片中的内容"
    },
    {
      "type": "image_url",
      "image_url": {
        "url": "https://signed-oss-url"
      },
      "min_pixels": 65536,
      "max_pixels": 8388608
    }
  ]
}
```

视频文件使用：

```json
{
  "type": "video_url",
  "video_url": {
    "url": "https://signed-oss-url",
    "fps": 2
  },
  "max_pixels": 655360
}
```

`qwen3.5-flash`的上下文上限很高，但视频帧仍会产生大量视觉 Token。默认应限制视频帧率、总像素和文件大小，不能把长视频原样无限传入。[官方多模态输入参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)

## 5. OSS 上传与后端接口

### 5.1 申请媒体上传地址

```http
POST /api/uploads/presign-media
X-Weiguang-User-ID: <local-user-id>
Content-Type: application/json
```

```json
{
  "filename": "receipt.png",
  "content_type": "image/png",
  "expires_seconds": 900
}
```

返回：

```json
{
  "object_key": "chat-attachments/<user>/<uuid>.png",
  "upload_url": "<short-lived-put-url>",
  "download_url": "<short-lived-get-url>",
  "headers": {"Content-Type": "image/png"},
  "expires_in": 900
}
```

### 5.2 校验规则

- 图片：最大 10 MB，最多 4 张/轮；
- 视频：最大 50 MB，最长 120 秒，最多 1 个/轮；
- 只接受明确的图片/视频 MIME 类型；
- 文件扩展名不能作为唯一校验依据；
- OSS 对象键必须包含用户隔离前缀，禁止路径穿越；
- 上传记录保存用户 ID、会话 ID、对象键、文件名、大小、MIME、创建时间和过期/删除状态；
- 失败请求清理未使用对象，定时任务清理过期附件。

## 6. 前端交互

### 6.1 聊天页

- 在文本输入区域增加“添加图片/视频”按钮；
- 选择后展示缩略图或视频封面、文件名、大小和移除按钮；
- 发送前先申请 OSS 签名地址并上传；
- 上传成功后将结构化附件加入当前用户消息；
- 发送期间显示附件上传状态和模型分析状态；
- 附件上传失败不提交 LLM 请求，并保留文本输入方便重试。

### 6.2 语音提问

```text
语音转写
→ 当前语音轮次绑定的图片/视频附件
→ qwen3.5-flash 视觉理解
→ 文本流式回答
→ Qwen TTS 朗读文本
```

语音输入期间不自动重复上传已绑定附件；附件只属于用户明确选择的当前轮次。

## 7. 历史记录与上下文

消息记录增加可选附件数组：

```json
{
  "kind": "text",
  "content": "请总结这张图",
  "attachments": [
    {
      "kind": "image",
      "object_key": "chat-attachments/.../a.png",
      "filename": "a.png",
      "content_type": "image/png"
    }
  ]
}
```

上下文构建规则：

1. 当前轮附件一定发送；
2. 最近文本消息按 Token 预算保留；
3. 历史附件默认只保留元数据，不重新加载原图/视频；
4. 用户明确说“刚才那张图”时，再根据消息 ID生成新的短期签名 URL；
5. 附件 URL过期后重新签名，不将永久 URL写入消息正文；
6. 纯文本轮次仍走 `/api/chat/stream`，不触发 TTS。

## 9. 安全与成本

- Qwen API Key只留在 FastAPI；
- OSS Bucket保持私有；
- 签名 URL设置短时过期；
- 不在日志打印签名 URL、原始视频或 Base64；
- 图片和视频会增加输入 Token 与延迟，发送前展示文件大小提示；
- 对每用户每日媒体上传量、总存储量和单轮附件数量做配额；
- 视频默认 `fps=2`，长视频优先提示用户裁剪；
- 发生 Qwen 多模态错误时，返回明确错误，不根据文件名猜测内容。

## 10. 实施阶段

### 阶段一：图片最小闭环

- 媒体签名上传；
- 图片预览和发送；
- `image_url` 结构化消息；
- Qwen 文本回答流式返回；
- 图片消息本地历史元数据保存。

### 阶段二：视频理解

- 视频上传和封面预览；
- `video_url` 与 `fps` 参数；
- 时长/大小/总像素限制；
- 视频上下文过期后重新签名。

### 阶段三：语音与多模态融合

- 语音提问携带当前附件；
- 文本回答继续交给克隆音色 TTS；
- 外放回声门控和长视频延迟提示；
- 图片/视频多模态轮次的浏览器验收。

## 11. 验收标准

- 上传图片后，Qwen 能回答图片中的可见内容；
- 上传视频后，Qwen 能回答视频中的主要画面和时间顺序；
- 文本输出仍保持流式；
- 语音提问图片/视频时，TTS 朗读的是视觉理解后的文本答案；
- 刷新后消息显示附件元数据，过期 URL可以重新签名；
- 其他本地用户无法读取当前用户的 OSS 对象；
- 单纯文本聊天不上传附件、不增加视觉 Token、不触发 TTS；
- 构建、后端迁移、图片接口、视频接口和 Chrome 外放语音场景全部通过。

## 12. 风险与未决事项

- 当前项目登录仍是本地兼容用户 ID，正式多用户前需要换成服务端认证主体；
- Qwen 视频输入的实际可接受时长、帧率和费用需以当前地域配额与模型返回为准；
- 视频音轨理解不属于 `qwen3.5-flash` 的本阶段目标，如需理解视频声音，应评估 `qwen3.5-omni-flash`；
- 图片/视频附件持久化需要与现有聊天记录 PostgreSQL 迁移统一设计；
- 方案完成前不得将本方案标题改为 `[已完成]`。
