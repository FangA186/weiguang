# [已完成] LLM 单次成本硬上限设计

> **状态**：已完成（Completed）
> **创建时间**：2026-09-07
> **完成时间**：2026-09-07

## 目标

套餐继续按“调用次数”向用户展示，但每次调用在服务端都有确定的输入与输出上限，防止超长消息、历史堆积或直接调用 API 将成本推入 128K 以上价格档。

## 输出预算

所有上限由后端调用场景决定，前端不得提交或覆盖：

| 场景 | `max_completion_tokens` |
|---|---:|
| 普通文字聊天 | 512 |
| 语音逐句计划（含 NDJSON 控制字段） | 1,024 |
| 动态纠偏 | 1,024 |
| 单张普通截图 OCR | 4,096 |
| 人设/记忆自动学习 | 8,192 |

`BailianLLMProvider` 的 `complete_with_usage`、`complete`、`stream_events` 增加必经的服务端参数。业务调用者只选择预定义场景，不接收用户自定义数值。

## 输入预算

1. 单轮用户文字最多 2,000 字符，前端显示计数，后端 Pydantic 再校验；附件说明计入正文。
2. 人设系统提示保留，但限制为 UTF-8 24KB；超限视为人设数据异常，不静默发送。
3. 当前用户消息完整保留；历史从最近向前选取，文字与 JSON 序列化后的 UTF-8 总量最多 48KB。
4. 最多保留当前会话最近一条视觉消息、4张图片或1段视频；其他附件不进入本轮上下文。
5. 超出历史预算时直接丢弃最旧历史，并记录 `context_trimmed_messages`。不额外调用摘要模型；长期信息由现有 Persona 和 Memories 承接。
6. 同一套裁剪器必须在普通聊天和语音聊天入口复用，防止某一路径漏限。

UTF-8 字节预算使用标准库即可，避免为了估算 Token 引入模型专属 tokenizer。48KB 对中文约为16K字符，对英文通常低于约12K Token，能够稳定留在官方 128K 最低价格档内。

## 成本上界

按北京地域输入≤128K的原价：输入0.2元/百万Token、输出2元/百万Token。普通聊天按约16K输入与512输出的极端上限估算：

- 单次约 `16,000×0.2/1,000,000 + 512×2/1,000,000 = 0.004224元`。
- Plus 1,000次约4.22元。
- Pro 3,000次约12.67元。

以上仅为LLM文本成本上界，不含TTS、图片和视频；它们已有独立套餐额度。

## 结算与监控

- 继续按实际 `prompt_tokens`、`completion_tokens` 记录供应商用量，同时在 `raw_usage` 保存 `requested_max_completion_tokens`、输入字节数和裁掉的消息数。
- 监控增加输入Token P95、输出Token P95、`finish_reason=length` 比例、每套餐平均单次文本成本。
- 达到输出上限时结束本轮，不自动“继续生成”，避免一次用户操作变成第二次隐藏调用。
- 先用硬上限控制成本，不增加用户可见的 Token 套餐或复杂积分规则；只有真实成本数据证明调用次数定价不可持续时再调整套餐。

## 验收

- 普通/语音/纠偏/OCR/人设请求体分别携带正确上限。
- 2,001字符用户输入被前后端拒绝；直接API同样不可绕过。
- 超长历史只裁最旧消息，当前消息、人设与最近视觉输入保留。
- 所有构造后的普通聊天输入低于预算，供应商实际输出不超过场景上限。
- 用量流水能回读实际Token、请求上限和裁剪数量；`length`停止不会自动续调。

## 验收总结

- 共享 `BailianLLMProvider` 强制要求调用者选择场景，并分别注入 512 / 1,024 / 4,096 / 8,192 的 `max_completion_tokens`；OCR 直连路径同步受限。
- 服务端限制当前聊天输入 2,000 字符、最多 200 条传入消息、系统提示 24KB、历史 48KB、文本请求总量 96KB，并只保留最近一条视觉上下文（最多4图和1视频）。
- `raw_usage` 已记录实际 Token、请求上限、输入字节数、裁剪条数与 `finish_reason`；管理端成本页新增输入/输出 P95、`length` 比例、裁剪量和各套餐平均单次文本成本。
- Provider 场景/裁剪自检、额度端点 Mock、语音自适应、人设/OCR解析、真实本地 PostgreSQL 原子回归、客户端和管理端生产构建均通过；测试数据库前缀数据已在 `finally` 清零。
- Chrome 登录态实测 2,001 字符及5张图片请求均在 Provider 前返回 422；运行中的 FastAPI 已热重载并保持健康。为避免消耗额度，本次未发送新的真实百炼生成请求。
