# [已完成] 生产监控 Web 页面与运营管理后台 UI 开发方案

> **状态**：已完成 (Completed)
> **创建时间**：2026-09-01
> **完成时间**：2026-09-02
> **前置能力**：`GET /api/admin/monitoring/summary`、`scripts/check_monitoring.py`
> **当前决策**：继续使用链动小铺；微信/支付宝直连暂缓；长期记忆后移

## 1. 目标

为唯一管理员提供统一后台，把生产监控、Token成本、权益交易、用户状态和对话内容集中到一个 Web 界面。监控页回答四个问题：

1. 最近 24 小时或 7 天调用是否正常；
2. 当前成本是多少，是否只是部分估算；
3. 失败、取消、过期与悬挂预留是否需要处理；
4. 哪个 Provider、模型或权益消耗异常。

## 2. 非目标

- 不建设微信/支付宝直连支付；链动小铺继续承担支付和发码。
- 不建设长期记忆/RAG。
- 不在第一版引入 Prometheus、Grafana、Sentry、消息队列或新的前端图表依赖。
- 不在页面修改价格和告警阈值；阈值继续由环境变量管理。
- 监控总览不展示个人数据；管理员进入用户详情后可直接查看完整邮箱、昵称、用户ID和对话正文。
- 永不展示完整卡密、Session Cookie、密码哈希或 Provider Key。
- 第一版不主动发送飞书/邮件/短信；保留现有告警脚本退出码作为调度接入点。

## 3. 页面与导航

### 3.1 路由

```text
/admin/monitoring      运行监控
/admin/costs           Token与成本
/admin/transactions    权益交易
/admin/users           用户管理
```

- 只允许已登录用户进入路由；最终权限由后端唯一管理员白名单校验。
- 普通账号收到 403 时展示“无监控权限”，不回退或泄露任何统计值。
- 第一版不在公开首页、套餐页展示入口；内部账号从个人中心进入“运营后台”。

### 3.2 页面层级

```text
顶部导航
  ├─ 页面标题、数据窗口、最后更新时间
  └─ 24小时 / 7天切换、手动刷新

关键指标
  ├─ 预估成本
  ├─ 请求总数
  ├─ 失败/取消率
  └─ 悬挂预留

  └─ critical 在前、warning 在后

  └─ 模型成本表

```

## 4. 后端 API 扩展

继续复用：

```http
GET /api/admin/monitoring/summary?hours=168&bucket=day
```

### 4.1 参数

| 参数 | 值 | 默认 | 说明 |
|---|---|---:|---|
| `hours` | `24` / `168` | `24` | 第一版页面只开放两个窗口 |
| `bucket` | `hour` / `day` | 随窗口决定 | 24小时按小时；7天按天 |

后端仍保留 `1–168` 小时校验，前端不开放任意输入，避免无意义查询。

### 4.2 保留现有字段

- `requests`
- `usage`
- `provider_usage`
- `cost`
- `subscriptions`
- `alerts`

### 4.3 新增字段

```json
{
  "series": [
    {
      "bucket_start": "2026-08-31T00:00:00Z",
      "completed": 12,
      "failed_or_cancelled": 2,
      "estimated_cost_cny": 0.04
    }
  ],
  "models": [
    {
      "provider": "bailian",
      "model": "qwen3.5-flash",
      "requests": 16,
      "estimated_cost_cny": 0.021875,
      "telemetry_missing": 3
    }
  ]
}
```

### 4.4 查询约束

- 对 `usage_events.occurred_at` 使用已有索引；只读取最近 7 天。
- 时间序列在 PostgreSQL 用 `date_trunc` 聚合，禁止先拉全量历史再由前端计算。
- 同一 LLM 请求只读取 `metric='ai_reply'` 的 raw usage，避免图片/视频权益流水重复计算 Token 成本。
- TTS 只读取 `metric='ai_voice_seconds'`；缺少 `usage_characters` 时进入遥测缺失，不按语音秒数伪造字符成本。
- 成本估算不抵扣免费额度和促销优惠，始终标注“预估”。

## 5. 成本口径

默认价格取阿里云百炼华北2公开价，并允许环境变量覆盖：

| 模型 | 输入 | 输出 |
|---|---:|---:|
| Qwen3.5-Flash，单请求 ≤128K Token | 0.2 元/百万 Token | 2 元/百万 Token |
| Qwen-Audio-3.0-TTS-Flash | 1 元/万计费字符 | 不计费 |

来源：[阿里云百炼模型价格](https://help.aliyun.com/zh/model-studio/model-pricing)。

页面显示：

```text
预估成本 ¥0.238975
部分估算 · 19 个完成请求缺少原始 Token/字符
```

禁止只显示一个没有可信度说明的成本数字。

## 6. 告警规则与 UI 映射

| 告警代码 | 条件 | UI | 首要动作 |
|---|---|---|---|
| `cost_budget_exceeded` | 窗口成本 ≥ 按时长折算预算 | 红色 critical | 检查异常调用和Provider账单 |
| `failure_rate_high` | 至少5次尝试且失败/取消率 ≥ 5% | 琥珀 warning | 查看断线、取消和上游错误 |
| `stale_reservations` | 超过TTL仍为reserved | 红色 critical | 检查结算任务和数据库锁 |
| `cost_telemetry_missing` | 完成请求缺Token/字符 | 琥珀 warning | 修补Provider raw usage采集 |

UI 原则：

- 告警列表始终显示；无告警时显示“当前窗口无活动告警”。
- 不以只有颜色的圆点表达严重级别，同时显示 `严重` / `警告` 文本。
- 告警不在页面内提供“忽略”或“已解决”按钮，避免把未持久化操作伪装成告警管理系统。
- 成本遥测缺失时，成本卡和趋势图统一显示“部分估算”。

## 7. 前端 UI 设计

### 7.1 视觉方向

- 延续微光现有深色、低饱和、暖金强调色。
- 页面是内部运营工具，减少营销装饰；背景、卡片和边框使用现有设计 Token。
- 数字使用等宽或 tabular numerals，成本保留6位小数，小于0.01元时避免显示成0。
- 绿色仅表示“正常”，红色仅表示 critical，暖金/琥珀表示 warning，灰色表示无数据。

### 7.2 顶部栏

- 左侧：`生产监控`、`内部只读`状态、窗口起止时间。
- 右侧：`24小时`、`7天`分段按钮；`刷新`按钮；“30秒后自动刷新”。
- 切换窗口立即请求新数据，旧数据保留并降低透明度，避免整页闪白。
- 页面隐藏时使用 Visibility API 暂停轮询，重新显示后立即刷新。

### 7.3 KPI

第一行固定四项：

1. **预估成本**：金额、预算、部分估算状态；
2. **请求总数**：完成/失败取消拆分；
3. **失败/取消率**：百分比和阈值；
4. **悬挂预留**：当前reserved与stale数量。

不增加“健康度分数”等没有权威计算依据的装饰指标。

### 7.4 趋势图

- 使用原生 SVG，不增加 ECharts/Chart.js。
- 成本图为单序列面积折线；纵轴单位元，横轴小时或日期。
- 请求图为完成与失败/取消两条折线；同一时间轴、共享悬浮提示。
- 数据不足2个点时展示空态，不绘制误导性趋势。
- 7天窗口最多7个点，24小时最多24个点，无需缩放、拖拽和复杂筛选。

### 7.5 用量与模型表

- 六类权益用紧凑横向条展示完成量，不与套餐上限混淆。
- 模型成本表字段：模型、请求、输入Token、输出Token、TTS字符、预估成本、遥测缺失。
- 默认按成本降序；第一版不提供用户级下钻，避免暴露个人数据。

### 7.6 订阅概览

- 只显示 `free / plus / pro × active / expired` 数量。
- 不展示用户列表。
- 免费体验明确为一次性，不写“下月重置”。

## 8. 页面状态

| 状态 | 页面表现 |
|---|---|
| 加载 | 保留页面骨架，按钮显示“刷新中” |
| 成功 | 更新时间变更，数字和图表原位更新 |
| 空数据 | 成本为 `¥0`，趋势区显示“当前窗口暂无调用” |
| 部分成本 | 成本卡、趋势标题和告警区同时标记“部分估算” |
| 403 | 单页显示“无监控权限”，提供返回首页 |
| 422 | 恢复24小时默认窗口并显示参数错误 |
| 503/网络错误 | 保留最近成功数据并标记“数据已过期”，允许重试 |

## 9. 响应式与可访问性

- ≥1024px：四个KPI同排，两张趋势图并排。
- 720–1023px：KPI两列，趋势图纵向排列。
- <720px：单列；表格允许容器内横向滚动，不压缩数字到不可读。
- 所有按钮有可见文字和键盘焦点。
- 图表包含 `<title>`、`<desc>` 和文字摘要；关键信息不依赖悬停。
- 告警容器使用 `role="status"`；critical 新增时使用 `aria-live="polite"`，不持续播报自动刷新。
- 遵循 `prefers-reduced-motion`，仅数值轻微过渡，不做循环动画。

## 11. 安全设计

- 后端继续以 HttpOnly Session 识别用户，不接受客户端传入 user_id 或 admin 标记。
- 页面路由守卫只改善体验，不能替代后端唯一管理员白名单鉴权。
- 监控接口只返回聚合结果；用户、交易和对话接口只允许唯一管理员访问。
- 用户详情直接返回完整邮箱和对话内容，不增加访问原因或审计流程。
- 禁用、启用和资料编辑使用普通确认，不增加操作原因字段。
- 前端不写 Local Storage；最近窗口只保存在组件内存。
- 监控数据禁止加入公开 `/api/health`。
- 价格和预算环境变量不允许通过页面修改。

## 15. 运营后台模块扩展

### 15.1 单管理员权限

- 只有当前唯一管理员账号可以访问 `/api/admin/*` 与 `/admin/*`。
- 第一版直接复用现有内部管理员白名单，不新增角色、权限矩阵和管理员成员表。
- 普通用户统一返回403；前端路由守卫只负责友好跳转。
- 将来出现第二个后台人员时，再立项增加RBAC。

### 15.2 数据库变更

按 `internal/auth/migrations/` 新增一份顺序迁移：

```text
app_users
  + status active|disabled
  + disabled_at
  + admin_note
```

- 禁用用户必须在同一事务更新 `app_users.status` 并删除其 `app_sessions`。
- 不能直接修改 `usage_events.quantity`、`subscription_grants` 或卡密状态来“充值”。权益调整必须另建不可变 adjustment 流水后由服务层执行。

### 15.3 Token与成本页面

顶部指标：

- LLM 输入Token；
- LLM 输出Token；
- TTS计费字符；
- 预估总成本与遥测覆盖率。

用户成本表：

| 字段 | 说明 |
|---|---|
| 用户 | 昵称 + 完整邮箱 |
| AI回复 | 完成次数 |
| 输入/输出Token | 从 `raw_usage.usage` 聚合 |
| TTS字符/秒数 | 成本字符与产品语音时长并列展示 |
| 预估成本 | LLM输入 + LLM输出 + TTS |
| 完整性 | 完整 / 部分估算 / 无成本遥测 |

- 默认按成本降序；支持24小时/7天。
- 不展示思维链内容，只统计Token。
- 点击用户跳转用户详情并直接加载对话正文。

### 15.4 权益交易页面

当前权威数据只能证明：

```text
卡密状态 → 兑换用户 → Plus/Pro grant → 生效/到期/撤销
```

不能证明链动小铺实际支付金额、支付渠道流水或退款到账。因此页面命名为“权益交易”，字段为：

| 字段 | 当前来源 |
|---|---|
| 用户 | `redemption_codes.redeemed_by_user_id` |
| 套餐 | `subscription_grants.plan_code` |
| 来源 | `source_channel=ldxp` |
| 兑换时间 | `redeemed_at` |
| 权益周期 | `period_start / period_end` |
| 状态 | 已发放 / 已撤销 / 已到期 |
| 套餐标价 | 59 / 129，仅参考 |
| 实付金额 | `渠道未同步` |

后续只有获得链动小铺API并新增外部订单账本后，才显示“实付金额、订单号、退款金额、到账状态”。禁止用套餐标价冒充用户充值金额。

### 15.5 用户管理

用户列表字段：昵称、完整邮箱、状态、套餐、到期日、7天成本、最近活跃时间、注册时间。

筛选：关键词、状态、套餐；服务端分页，每页20条。

允许操作：

- 编辑昵称；
- 增加内部备注；
- 禁用/启用账号；
- 查看用量、权益交易和对话正文。

禁止操作：

- 查看或修改密码；
- 无验证修改邮箱；
- 直接改套餐到期日或已用额度；
- 以用户身份登录或冒充用户；
- 批量导出对话正文。

禁用确认框必须展示影响：立即注销所有会话、拒绝新Provider请求、保留历史数据；不要求填写原因，且不能禁用自己。

### 15.6 用户对话与消息查看

管理员选择用户后直接显示对话列表和最近消息正文，不增加访问原因弹窗、审核状态或审计日志。

对话按时间顺序展示用户输入和AI输出；支持切换历史会话和分页加载。

消息气泡展示：角色、文本/语音类型、状态、时间、音频时长、附件数量。第一版不自动播放用户或AI音频，不自动打开图片/视频。

- 所有写接口继续受可信Origin和HttpOnly Session保护。
- 对话正文可直接GET，但仍必须通过唯一管理员白名单。

### 15.8 隐私与发布门槛

- 上线用户对话查看前应在隐私政策说明管理员可能为运营和故障排查访问内容。
- 唯一管理员账号必须使用独立强密码；后续上线公网前增加MFA。
- 具体消息保留期限需另行确认。
- 第一版禁止全文跨用户搜索，避免形成大规模内容检索工具。
- 禁用会话撤销和普通用户403必须验收后才能上线用户管理。
