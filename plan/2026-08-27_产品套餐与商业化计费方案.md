# [未完成] 微光产品套餐与商业化计费方案

> **状态**：未完成 (Pending)
> **创建时间**：2026-08-27
> **适用阶段**：首批 50 名注册用户的邀请测试与小规模付费验证
> **当前建议**：首发采用“免费体验 + Plus 59 元/月 + Pro 129 元/月”三档，不承诺无限语音或无限多模态

## 1. 方案目标

本方案把微光现有的文字陪伴、浏览器转写轮次语音、授权声音复刻、图片/视频理解、聊天截图导入和历史记忆能力，整理为用户可理解、系统可计量、成本可控制的套餐。

第一阶段优先验证三个问题：

1. 用户是否愿意为“自己的授权音色 + 持续记忆 + 中文语音陪伴”付费；
2. 59 元与 129 元两个价格带的转化和使用强度；
3. 真实 LLM、TTS、多模态、存储和基础设施成本是否落在预算内。

本方案只完成产品与计费设计，不代表支付、订阅、退款、真实额度扣减已经实现。

## 2. 当前产品与实现边界

### 2.1 可进入套餐的现有能力

- 文本对话与聊天历史；
- 轮次语音对话：浏览器 `SpeechRecognition` 转成文本后执行 LLM → TTS；
- 用户授权参考音频的声音复刻；
- AI 回复按需朗读；
- 图片和视频理解；
- 聊天截图提取、人工校对和导入；
- 角色设定和历史会话；长期记忆仍是后续规划能力。

### 2.2 当前不能对外承诺的能力

- 不能宣传全双工、实时打断或 25 路同时无排队；
- 真实声音复刻、浏览器长回复和 25 路压测仍未全部验收；独立 ASR 已决定暂不接入；
- 当前前端 `localProfile()` 仍使用本地匿名资料和 `999999` 假额度，FastAPI 也没有完整的订阅、订单、支付回调和真实配额服务；
- 不承诺用户克隆音色可用于商业配音、公开传播或第三方声音复刻；商业用途需要单独的权利证明和法律条款；
- 不提供“无限使用”，也不把供应商 RPM 解释为用户可用并发数。

## 3. 套餐设计原则

1. **先卖核心价值**：套餐差异围绕陪伴深度、语音时长、记忆和多模态，不围绕底层模型名称。
2. **首期只设三档**：免费、Plus、Pro 足够验证需求；没有独立创作者工作流前不单设 Creator。
3. **用户口径简单**：前台只展示 AI 回复次数、语音分钟、多模态次数和可用音色数；后台保留供应商原始计费单位。
4. **失败不扣额度**：供应商失败、服务端异常或内容审核拦截不扣；成功生成后因用户主动关闭页面不返还已经消耗的额度。
5. **付费额度按周期重置，免费体验仅一次**：Plus/Pro 每 30 天重置且不结转；免费体验只发放首次 7 天，到期后必须购买或兑换套餐。
6. **一个账号只允许一个前台对话任务**：套餐只影响排队优先级，不出售同账号多开会话，避免账户共享和异常消耗。

### 4.2 为什么不沿用 49.9 / 89.9 / 169.9 四档

- 首期只有约 50 名用户，三个付费档会让每档样本过小；
- 现有产品没有足够清晰的 Creator 专属功能，169.9 元档容易变成单纯堆额度；
- 59 元接近国内数字会员的常见心理价位，129 元则用于验证高频语音和深度记忆的溢价；
- 两个付费档更容易比较转化、留存、额度消耗和毛利。

国际市场可作为价格锚点但不能直接照搬。Character.AI 官方当前列出的 c.ai+ 为 9.99 美元/月、94.99 美元/年，并把更好的记忆、优先访问、最新模型和语音通话作为 Plus 权益；微光的用户规模、中文语音供应链和声音复刻责任不同，因此只用于验证 59 元价位并不脱离市场，而不用于推导成本。

## 5. 额度定义与扣减规则

### 5.1 AI 回复次数

以下行为在成功生成完整 AI 回复后扣 1 次：

- 纯文本消息；
- 麦克风语音转写后产生的 AI 回复；
- 携带图片或视频的消息；
- 对已导入聊天记录继续提问。

以下行为不扣 AI 回复次数：

- 打开历史、查看设置、试听已有音色；
- AI 回复的首次自动朗读；
- 同一条 AI 回复的按需朗读，只扣语音分钟；
- 供应商失败、超时、服务端异常和审核拦截。

### 5.2 AI 语音时长

“AI 语音时长”按秒累计并向用户展示分钟，只包含：

```text
AI 实际生成的 TTS 音频秒数
+ 对历史 AI 消息进行按需朗读产生的音频秒数
```

用户麦克风由浏览器 `SpeechRecognition` 转写，当前不接入独立 ASR，因此用户说话时长不进入套餐计费。微光服务端只统计实际生成的 TTS 音频；浏览器识别失败不扣额度。

### 5.3 多模态次数

- 图片按实际张数扣减；一条消息最多 4 张，沿用当前上传限制；
- 视频按文件条数扣减，并继续执行大小、时长和格式限制；
- 聊天截图导入按批次和批内图片上限控制，不与普通图片额度混用；
- 同一文件重复上传不自动免扣，后续可通过文件哈希做幂等防重。

### 5.4 音色权益

- “活跃音色数”表示可在产品中切换使用的音色槽位，不表示可以无限创建后删除；
- 所有声音复刻必须保存本人或权利人授权确认；
- 删除音色前需二次确认，供应商侧删除成功后再释放槽位；
- 免费用户的试用音色可长期保留，但超过 90 天未活跃时可提示用户重新确认；最终清理策略应与隐私政策一致；
- 不允许用多个账号规避音色槽位、免费额度和授权审核。

百炼官方当前说明：Qwen-Audio-TTS 创建音色免费；Qwen-TTS 创建音色为 0.01 元/个；相关音色配额各为最多 1000 个，单个音色过去 1 年未用于合成会被自动清理，且音色与创建时的目标模型绑定，不能跨模型直接使用。产品必须保存 `provider`、`target_model`、`voice_id`、授权状态和最后使用时间。

官方参考：[阿里云百炼声音复刻指南](https://help.aliyun.com/zh/model-studio/voice-cloning-user-guide)

### 6.2 单位成本假设

套餐试算暂按以下产品假设，后续必须用真实埋点替换：

- TTS 平均语速：220 个中文汉字/分钟；
- 中文每字按 2 个计费字符；
- 每轮 LLM 平均输入 2,000 tokens、输出 150 tokens；
- 供应商重试、标点和异常冗余按原始 API 成本的 2 倍设置安全系数；
- 基础设施预算为 700–1,200 元/月，不含研发、客服、获客、税费和支付通道费。

据此估算：

- TTS 输出 1 分钟约为 `220 × 2 ÷ 10,000 × 1 = 0.044 元`；
- 一轮 2,000 输入 + 150 输出的 LLM 约为 `0.0007 元`；
- 1 分钟 AI 语音输出加一轮 LLM 的原始 API 成本约 0.045 元，加入 2 倍安全系数后按约 0.09 元预算。

这些数字只用于定价试算。视频 token、图片 token、对象存储、下载流量和失败重试必须按请求单独记录，不能从平均值反推账单。

### 6.3 50 用户场景下的收入覆盖

| 用户结构 | 月收入 | 判断 |
|---|---:|---|
| 30 免费 + 15 Plus + 5 Pro | 1,530 元 | 只能接近低成本技术账单，不足以覆盖运营成本 |
| 20 免费 + 20 Plus + 10 Pro | 2,470 元 | 可覆盖约 1,450–2,150 元的基准技术成本，仍不含人力与获客 |
| 10 免费 + 25 Plus + 15 Pro | 3,410 元 | 有较健康的技术成本缓冲，可继续验证留存和扩容 |

首期目标不是立即形成完整利润，而是至少达到：

- 付费率 ≥ 40%；
- Pro 占付费用户 ≥ 25%；
- 模型 API + 基础设施成本不超过实收收入的 70%；
- 退款、支付通道费和税费加入后仍不出现单个重度用户持续负毛利。

## 7. 首发促销与加量包

### 7.1 邀请测试价

- 前 20 名付费用户首月：Plus 49 元、Pro 99 元；
- 次月自动恢复 59 元和 129 元，购买页必须显著展示续费价；
- 不提供“永久早鸟价”，避免后续额度和供应商价格变化时无法调整；
- 第一阶段不卖年付，至少运行两个完整自然月并验证退款、续费和成本后再开放。

### 7.2 加量包

首发只提供一个组合加量包，避免用户理解多个点数体系：

| 加量包 | 价格 | 内容 | 有效期 |
|---|---:|---|---:|
| 微光加油包 | 19.9 元 | 300 次 AI 回复 + 120 分钟语音 + 20 张图片 + 2 条视频 | 90 天 |

加量包先消耗月度套餐额度，再消耗有效期最短的加量包。取消会员后，加量包在有效期内仍可使用，但 Pro 专属功能不随加量包保留。

## 8. 产品页面与用户体验

### 8.1 套餐页展示顺序

1. 一句话价值：用经过授权的熟悉声音，获得有记忆的文字与语音陪伴；
2. 三张套餐卡，默认突出 Plus；
3. 权益对比表；
4. 语音分钟、AI 回复和多模态的计量解释；
5. 声音授权、AI 身份、隐私与删除说明；
6. 自动续费、取消、退款和额度重置规则。

### 8.2 个人中心

现有“次数可用请求”需改为四块可独立查看的用量：

- AI 回复：已用 / 总量；
- 语音：已用分钟 / 总分钟；
- 图片与视频：分别已用 / 总量；
- 音色：活跃数 / 槽位数。

当额度达到 70%、90%、100% 时分别提示；达到 100% 后允许继续查看历史和导出/删除数据，但阻止新的收费型请求，并提供升级或购买加量包入口。

### 8.3 套餐降级

- 降级在当前付费周期结束后生效；
- 历史数据不立即删除；如果超过降级后保留策略，先提供不少于 30 天的导出和删除提醒；
- 超过新套餐音色槽位时，保留用户选择的音色，其余标为暂停，不自动删除供应商音色；
- 已开始的后台导入任务允许完成，但完成后不能继续创建超额任务。

## 9. 计费与订阅技术方案

### 9.1 数据模型

当前代码已经出现 `backend/migrations/`，但项目 `AGENTS.md` 仍强制要求数据库迁移放在 `internal/auth/migrations/`，两者存在规范冲突。实施前必须先统一并更新迁移入口；在规范未正式调整前，新增迁移仍按 `internal/auth/migrations/` 的递增编号规则执行，不能静默绕过项目规范。

```text
plans
  id, code, name, monthly_price, status, version, effective_at

plan_entitlements
  plan_id, metric, monthly_limit, hard_limit, metadata

subscriptions
  id, user_id, plan_id, status, period_start, period_end,
  cancel_at_period_end, payment_channel, external_subscription_id

usage_events
  id, user_id, request_id, metric, quantity, provider,
  model, raw_usage, status, occurred_at

quota_buckets
  user_id, metric, source_type, source_id, granted,
  consumed, expires_at, version

orders
  id, user_id, product_type, product_id, amount,
  status, payment_channel, external_order_id, created_at, paid_at
```

`usage_events.request_id + metric` 建立唯一约束，所有预留、确认和返还必须幂等。`raw_usage` 只保存供应商计费元数据，不保存 API Key、Authorization、原始音频或完整私密对话。

### 9.2 API 边界

```text
GET  /api/plans
GET  /api/billing/summary
GET  /api/billing/usage
POST /api/billing/checkout
POST /api/billing/cancel
POST /api/billing/webhooks/{channel}
```

支付通道尚未确定，首期不要在业务代码中写死微信、支付宝或 Stripe。使用统一 `PaymentProvider` 接口，外部支付回调先验签、再幂等更新订单与订阅，不能相信前端传回的支付成功状态。

### 9.3 请求扣减闭环

```text
鉴权
  → 检查订阅与权益
  → 原子预留额度
  → 调用 LLM / TTS / 多模态
  → 成功：按真实 usage 确认
  → 失败：返还预留额度
  → 异步写入供应商成本和监控指标
```

实时音频转发与 SSE 推送不能被数据库慢查询阻塞。用量事件写入可通过异步队列完成，但额度预留必须在请求进入供应商前完成，且必须有超时回收任务。

### 9.4 外部售卖渠道：链动小铺兑换码

链动小铺可作为 Plus / Pro 的外部卡密售卖渠道，但不能取代微光的订阅账本。首期流程为“链动小铺自动交付一次性兑换码 → 登录微光兑换 → 数据库原子授予权益”，不依赖未核验的链动小铺订单回调或 API。具体数据模型、兑换规则、运营对账和自动化准入门槛见 [`plan/2026-08-29_链动小铺套餐兑换码售卖接入方案.md`](./2026-08-29_链动小铺套餐兑换码售卖接入方案.md)。

## 10. 分阶段落地

### 阶段 0：只埋点，不收费

- [ ] 替换 `999999` 本地假额度，接入真实用户身份；
- [ ] 为所有 LLM、TTS、多模态、截图导入请求记录原始 usage；浏览器转写不产生服务端 ASR usage；
- [ ] 建立按用户、模型、日期的成本看板；
- [ ] 用 3–5 名内部用户跑满至少 7 天，校准语速、回复长度和视频成本。

**完成标准**：同一批请求在项目看板的估算费用与供应商账单偏差不超过 10%。

### 阶段 1：影子配额

- [ ] 建立 plans、entitlements、usage_events 和 quota_buckets；
- [ ] 按套餐计算用量但不真正阻断请求；
- [ ] 验证跨月重置、失败返还、重试幂等和并发扣减；
- [ ] 完成 1/5/10/25 路压测和队列优先级验证。

**完成标准**：无重复扣减、无负额度、无跨用户串账；25 路超限时按预期排队或降级。

### 阶段 2：邀请付费

- [ ] 接入一个支付通道的沙箱和正式环境；
- [ ] 上线套餐页、订单页、个人中心用量和取消续费；
- [ ] 仅向前 20 名邀请用户开放首月价格；
- [ ] 建立退款、支付失败、回调重放和对账流程。
