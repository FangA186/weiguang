# [未完成] 语音中断取消与计费一致性方案

> **状态**：未完成 (Pending)
> **创建时间**：2026-08-31

## 目标

用户中断 AI 语音时，同时停止本地播放、浏览器 SSE 和服务端 LLM/TTS 上游；套餐只结算中断前已经发送的 PCM。中断不显示接口错误，未完成音频不保存为完整缓存。

## 最小改造

1. 聊天页和全屏语音页的每个语音回合创建独立 `AbortController`，传入 `/api/chat-and-tts/stream`。
2. 光球中断、关闭语音、页面卸载时调用 `abort()`；普通播放器停止不扩大为请求取消。
3. `submitTurn` 区分主动中断与真实异常：保留已返回文字，不追加错误气泡，不保存残缺音频。
4. 验证服务端取消后关闭 Provider 流，并只确认已经发送的 PCM 秒数。

## 验收标准

- 中断后不再收到后续 `audio.delta`，Provider 流关闭。
- 已发送 PCM 按实际字节结算，未发送部分不计入。
- 中断不出现“百炼 API 暂时不可用”。
- 正常完成仍保存完整音频缓存，缓存重播不产生新 TTS 用量。
- 前端生产构建、额度端点回归和真实本地 SSE 中断验证通过。
