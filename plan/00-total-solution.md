# 微光长期记忆总方案

## 1. 建设目标

用户可以上传多份聊天记录，让微光在后续文本和语音对话中具备可控、可解释、可删除的长期记忆。

每份数据独立形成一个记忆库，例如“工作聊天”“家庭聊天”“项目聊天”。每次对话开始前选择一个记忆库，模型只使用该记忆库的数据。

长期记忆由以下数据共同组成：

```text
清洗后的原始消息
  + 图片及其 OCR/视觉描述
  + 可检索消息片段
  + 结构化长期事实
  + 时间/主题摘要
  + 当前会话滚动摘要
```

## 2. 当前项目边界

当前计划采用的纯云 API 语音链路为：

```text
MiMo-V2.5-ASR → qwen3.5-flash → Qwen3-TTS-VC-Realtime
```

当前语音与多模态链路统一按云端 API 接入，新链路尚需接入。新增长期记忆后，由 `MemoryService` 和 `MemoryRetriever` 在模型请求前构建有限长度的记忆上下文。

文本和语音的回答正文必须由同一个文本模型生成，TTS 只负责朗读最终正文，防止页面文字与语音内容不一致。

## 3. 总体数据流

### 数据导入

```text
上传 JSON/ZIP
  ↓
文件校验与安全解压
  ↓
规范化消息
  ↓
删除视频、音频和未知附件
  ↓
保留并清洗图片
  ↓
保存消息与图片元数据
  ↓
切分检索片段
  ↓
生成 Embedding
  ↓
提取事实和摘要
  ↓
记忆库版本切换为 ready
```

### 对话调用

```text
用户选择记忆库
  ↓
session.start(memory_collection_id)
  ↓
加载记忆库摘要和重要事实
  ↓
用户输入文本、语音或实时会话多模态附件
  ↓
MemoryRetriever 检索相关记忆
  ↓
按模型预算组装上下文
  ↓
MiMo-V2.5 生成文本回答
  ↓
页面展示文本
  ↓
语音模式由 Qwen3-TTS-VC-Realtime 朗读同一文本
```

## 4. 记忆分层

| 层级 | 内容 | 使用方式 |
|---|---|---|
| L0 | 当前问题 | 永远完整保留 |
| L1 | 最近几轮当前会话 | 按 token 预算保留 |
| L2 | 当前会话滚动摘要 | 用于压缩和断线恢复 |
| L3 | 高重要度长期事实 | 相关时优先注入 |
| L4 | RAG 相关消息片段 | 达到相关性阈值才注入 |
| L5 | 原始低重要度消息 | 不主动注入，仅供检索 |

## 5. 上下文预算

### 文本模式

推荐预算：系统规则 600 token、事实 800 token、摘要 1,000 token、RAG 1,500 token、近期历史 2,500 token，剩余空间留给当前问题和回答。

### 语音模式

推荐预算：角色规则 300 token、事实 400 token、摘要 500 token、RAG 600 token、近期历史 700 token。普通语音回答限制为 50～150 字，复杂回答分段输出。

当前两阶段链路中，长期记忆由文本模型检索和理解，TTS 不承担历史理解；不在当前版本引入单模型端到端语音路线。

## 6. 核心技术决策

- PostgreSQL 保存消息、事实、摘要、会话和索引元数据。
- `tsvector + GIN` 做关键词检索。
- `pgvector + HNSW` 做语义检索。
- Redis 保存任务进度、Embedding 缓存和查询缓存。
- 独立 worker 处理图片、Embedding、事实提取和摘要。
- 记忆库使用版本号，重建完成后原子切换。
- 事实记录重要度、置信度和有效期，允许冲突、修订与过期。
- 每个会话绑定一个记忆库和一个记忆版本。
- 图片默认使用 OCR/描述参与检索，命中且模型支持视觉时才附带原图。

## 7. 核心数据表

| 表 | 作用 |
|---|---|
| `memory_collections` | 记忆库名称、状态、版本、统计和全局摘要 |
| `memory_imports` | 上传文件、清洗进度、错误和报告 |
| `memory_messages` | 清洗后的原始消息 |
| `memory_assets` | 图片、缩略图、OCR 和视觉描述 |
| `memory_chunks` | 全文与向量检索片段 |
| `memory_facts` | 结构化长期事实 |
| `memory_summaries` | 全局、主题、时间段和会话摘要 |
| `conversation_sessions` | 会话、provider、记忆库版本和滚动摘要 |
| `conversation_messages` | 当前产品内产生的文本/语音对话正文 |

## 8. 第一版非目标

- 不自动解析所有平台私有导出格式。
- 不保存视频原文件。
- 不自动把所有新聊天升级为长期事实。
- 不在一个会话里混合多个记忆库。
- 不在每轮加载全部图片。
- 不把完整聊天记录直接拼进 Prompt。

## 9. 完成标准

- 上传两份聊天数据后可以形成两个隔离的记忆库。
- 视频不落库，图片可预览并参与检索。
- 文本和语音能召回相同核心事实。
- 长上下文不会导致模型请求超限。
- RAG 平均检索耗时不超过 400ms。
- TTS 朗读内容与页面最终文本一致。
- 删除记忆库后消息、索引和图片不可访问。
