# [未完成] 阿里云百炼国内 API 语音对话架构与分阶段实施方案

> **状态**：未完成 (Pending)  
> **创建时间**：2026-08-23  
> **适用范围**：首期最多 50 个注册用户，目标 25 路同时进行一轮语音对话。  
> **前置决策**：不部署任何模型；LLM 与 TTS 统一接入阿里云百炼华北 2（北京），LLM 使用 `qwen3.5-flash`，默认克隆音色 TTS 使用 `qwen-audio-3.0-tts-flash`；ASR 暂按既定决策使用 Xiaomi MiMo，待后续单独评估是否迁移到百炼 ASR。

## 1. 目标与边界

### 1.1 首期目标

- 用户可以上传授权参考音频，创建并管理一个或多个克隆音色。
- 用户可以通过文本、麦克风、图片和视频进行轮次对话。
- 麦克风语音采用“录音 → ASR → LLM → TTS → 网页播放”的链路。
- TTS 使用用户的克隆音色；TTS 只朗读 LLM 已生成并展示的文本。
- 单轮结果支持文本和音频同时返回，音频可流式播放。
- 通过配额、队列和限流保护云 API 成本，不对外承诺未经压测的 25 路无排队并发。

### 1.2 明确不做

- 不部署本地模型、GPU Worker、模型权重或推理服务。
- 首期不做全双工打断式语音；用户说完一轮后再生成回答。
- 不让浏览器直接持有 Qwen 或 MiMo 密钥。
- 不用 Qwen Omni 的内置音色替代用户克隆音色主链路。

## 2. 总体架构

```text
┌────────────────────── 浏览器 Vue 3 ──────────────────────┐
│ 文本输入 │ MediaRecorder 录音 │ 图片/视频上传 │ 音频播放队列 │
└───────────────┬───────────────┬───────────────┬───────────┘
                │ HTTPS/WSS     │ HTTPS         │ WSS/HTTPS
                ▼               ▼               ▼
┌────────────────────── API 服务（Python/FastAPI） ──────────────────────┐
│ 鉴权 │ 会话 │ 文件校验 │ 配额/限流 │ 对话编排 │ 统一错误与审计 │
│              Provider Adapter（Bailian Qwen / MiMo）                    │
└─────────────┬───────────────┬───────────────┬──────────────────────────┘
              │               │               │
              ▼               ▼               ▼
       MiMo ASR API    阿里云百炼 LLM API  阿里云百炼 TTS API
                      qwen3.5-flash       qwen-audio-3.0-tts-flash
              │               │               │
              └───────────────┴───────────────┘
                              ▼
                    文本答案 + 音频流返回浏览器

API 服务旁路：
  PostgreSQL（用户、会话、消息、音色、配额、账单）
  Redis（短期会话、并发信号量、队列、限流、幂等锁）
  阿里云 OSS（参考音频、上传附件、音频缓存、审计文件）
  OpenTelemetry/结构化日志（延迟、用量、错误、成本）
```

## 3. 技术选型

| 层 | 选型 | 选择理由 |
|---|---|---|
| Web 前端 | Vue 3 + TypeScript + Vite | 当前目录已有 Vue 工程；适合保留现有聊天、音频播放和设置 UI |
| 录音 | 浏览器 `MediaRecorder`，优先 `audio/webm;codecs=opus`，服务端统一转码 | 不在浏览器运行 ASR 或本地模型；兼容桌面和移动端 |
| API 服务 | Python 3.12 + FastAPI + Uvicorn | 目标后端选型；异步 HTTP、WebSocket 和文件上传成熟 |
| HTTP 客户端 | `httpx.AsyncClient` | 连接池、超时、重试和异步调用统一封装 |
| Qwen LLM | 阿里云百炼华北 2（北京）`qwen3.5-flash`，OpenAI-compatible adapter | 国内地域、价格低、支持文本/图片/视频，作为默认 LLM |
| ASR | Xiaomi MiMo-V2.5-ASR API | 麦克风语音先转文本，避免把音频送入更昂贵的全模态 LLM |
| TTS | 阿里云百炼 `qwen-audio-3.0-tts-flash`；`qwen3-tts-vc-2026-01-22` 作为低成本 HTTP 降级 | 支持用户克隆音色、情绪/语速指令；HTTP/WebSocket 均可接入 |
| 音频播放 | Web Audio API / AudioWorklet 队列 | 按序播放 PCM/Opus/MP3 片段，避免多段音频重叠 |
| 数据库 | PostgreSQL 16 + `pgvector` | 用户、会话、消息、配额和记忆统一存储；保留现有记忆/RAG 设计 |
| 缓存/队列 | Redis 7 | 并发信号量、短队列、幂等锁、会话缓存和限流计数 |
| 文件存储 | 阿里云 OSS，华北 2（北京）、标准存储-本地冗余（LRS） | 与百炼同地域；参考音频和附件不放本地磁盘，便于签名访问和生命周期管理 |
| 反向代理 | Nginx 或云负载均衡 | TLS、静态资源、WSS 转发和基础限流；不购买独立高价 API Gateway |
| 任务执行 | Redis Streams/RQ（首期） | 音色创建、媒体清理、账单汇总等后台任务与请求链路隔离 |
| 监控 | Prometheus + Grafana + Sentry/结构化日志 | 观察首字节延迟、队列等待、API 错误、成本和配额 |
| 部署 | 1 台普通 CPU 应用机起步，Docker Compose 运行基础设施 | 模型在云端，首期不需要 GPU；后续按 API 并发扩展应用层 |

## 4. 服务边界与数据流

### 4.1 语音对话

1. 浏览器创建 `conversation_id`，录音并上传 `audio` 文件。
2. API 服务校验用户、文件大小、时长、MIME 类型和额度。
3. `AsrProvider` 调用 MiMo ASR，保存转写文本和 ASR 用量。
4. `LlmProvider` 将转写、会话摘要、RAG 结果及多模态附件传给 `qwen3.5-flash`。
5. LLM 先把文本增量写入响应；完整或分段文本交给 `TtsProvider`。
6. TTS 使用用户绑定的 `voice_id`，通过 WSS/HTTP 返回音频片段。
7. 浏览器按序播放并展示字幕；服务端异步保存消息、用量和错误信息。

### 4.2 声音克隆

1. 客户端申请上传地址，服务端生成 OSS 短时签名上传 URL。
2. 用户上传授权参考音频；服务端检查时长、采样率、文件类型和授权声明。
3. 后台任务调用 Qwen 声音克隆 API，保存 `provider_voice_id`、目标 TTS 模型、状态和错误。
4. 音色创建必须幂等：相同用户、文件哈希和模型不得重复创建。
5. 删除音色时同时删除 provider voice（若 API 支持）、对象存储文件及业务记录。

### 4.3 多模态附件

- 文本、图片、视频：发送给 `qwen3.5-flash`，附件由对象存储 URL 或受控 Base64 传递。
- 音频附件：普通麦克风走 MiMo ASR；要求模型直接理解音频内容时才路由 Omni/MiMo。
- 附件必须绑定用户和会话，设置大小、时长、格式、病毒扫描和生命周期策略。

## 5. 后端模块建议

```text
backend/
  app.py                 # FastAPI 启动与路由注册
  config.py              # 环境变量与启动校验
  api/                   # 鉴权、会话、音色、上传、健康检查
  providers/             # qwen_llm.py、qwen_tts.py、mimo_asr.py
  services/              # 对话编排、音色、配额、多模态路由
  jobs/                  # 音色创建、清理、账单汇总
  repositories/          # PostgreSQL、Redis、对象存储
```

现有前端页面和播放组件优先保留；在 `backend/` 建立新 API 后，替换 `frontend/src/api` 和 `frontend/src/lib/realtimeClient.ts` 中的旧模型协议适配，不在本阶段重做 UI。

## 6. 配置与安全

生产环境只通过密钥管理服务或环境变量注入：

```text
QWEN_API_KEY                 # 阿里云百炼北京 API Key（已配置到本地环境）
QWEN_BASE_URL=https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
QWEN_LLM_MODEL=qwen3.5-flash
QWEN_TTS_MODEL=qwen-audio-3.0-tts-flash
QWEN_TTS_FALLBACK_MODEL=qwen3-tts-vc-2026-01-22
MIMO_API_KEY
MIMO_BASE_URL
DATABASE_URL
REDIS_URL
OSS_REGION=cn-beijing
OSS_BUCKET
OSS_PUBLIC_ENDPOINT=https://oss-cn-beijing.aliyuncs.com
OSS_INTERNAL_ENDPOINT=https://oss-cn-beijing-internal.aliyuncs.com
OSS_ACCESS_KEY / OSS_SECRET_KEY
PUBLIC_BASE_URL
```

- API Key 只存在后端，日志禁止输出完整密钥、上传内容和原始音频。
- 音频授权记录、用户删除请求和 provider voice 映射必须可审计。
- 所有外部请求设置连接、读取、总耗时和空闲超时；重试只对网络错误和明确的 429/5xx 生效。
- WSS 音频流必须绑定用户会话，断开时释放 Redis 信号量。

## 8. 首期接口草案

```text
POST   /api/uploads/presign
POST   /api/voice-clones
GET    /api/voice-clones/{id}
DELETE /api/voice-clones/{id}
POST   /api/conversations/{id}/messages
POST   /api/conversations/{id}/audio-turn
WS     /api/conversations/{id}/audio-stream
GET    /api/conversations/{id}/messages
GET    /api/usage/me
GET    /api/health/ready
```

所有接口返回 `request_id`。音频轮次返回 `transcript`、`answer_text` 和 `audio_url` 或音频流事件，前端不直接拼接供应商协议。

## 9. 风险与回滚

| 风险 | 处理 |
|---|---|
| 阿里云百炼 TTS 实时并发不足 | 降级 `qwen3-tts-vc-2026-01-22` HTTP VC、短队列、限制套餐并发 |
| 供应商 429/5xx | 指数退避、熔断、备用地域或暂时关闭语音，只保留文本回答 |
| 音色创建失败 | 保留任务状态，允许重试；避免重复扣费 |
| 浏览器格式兼容 | 服务端转码为统一格式；前端保留 PCM/Opus/MP3 适配 |
| 成本超预算 | Redis 配额、每日预算、按用户限额和异常告警 |

最低可用回滚状态是“关闭语音、保留文本聊天”，不保留模型部署回退路径。
