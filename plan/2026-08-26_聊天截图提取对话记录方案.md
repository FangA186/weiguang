# [未完成] 聊天截图提取对话记录方案

> **状态**：未完成 (Pending；代码已交付，真实素材验收与多图顺序校验待补)
> **创建时间**：2026-08-26
> **适用范围**：微光用户主动上传的微信或其他聊天截图
> **前置决策**：不读取微信本地数据库、不破解聊天备份、不承诺一键导入微信全部记录；只处理用户主动上传并确认的截图。

## 1. 目标

实现一条可控的截图导入流程：

```text
上传聊天截图
→ OCR/视觉理解
→ 提取说话人、消息文本、时间和顺序
→ 用户预览与修正
→ 用户确认
→ 保存为聊天记录或 Agent 记忆
```

第一版重点是把截图转成可靠的结构化对话，不直接让 Agent 无审核地“学习”截图内容。

## 2. 产品边界

### 2.1 支持

- 微信聊天截图；
- 其他 IM、短信或社交平台聊天截图；
- 单张或多张截图；
- 左侧/右侧气泡识别；
- 显示名称、相对位置、消息文本、时间和图片顺序提取；
- 用户确认后保存为导入记录；
- 从导入记录中选择内容提取长期记忆。

### 2.2 不支持

- 直接读取微信账号；
- 解析微信加密数据库或备份文件；
- 未经用户确认自动写入 Agent 长期记忆；
- 仅凭气泡颜色或头像猜测真实身份；
- 承诺所有截图都能 100% 还原原始聊天。

## 3. 总体架构

```text
Vue 前端
  ├─ 选择/粘贴截图
  ├─ 预览与排序
  └─ 提交提取任务
        │
        ▼
FastAPI
  ├─ OSS 临时上传与用户归属校验
  ├─ 截图尺寸/格式/数量限制
  ├─ Qwen3.5-Flash 视觉理解
  ├─ JSON 结构化校验
  └─ 用户确认后写入 PostgreSQL
        │
        ├─ chat_import_batches
        ├─ chat_import_messages

```

Qwen3.5-Flash 官方支持图片输入和文本输出；请求使用 OpenAI-compatible Chat Completions 的 `content` 数组和 `image_url` 内容块。[官方模型说明](https://help.aliyun.com/zh/model-studio/qwen3-5-flash) [官方 Chat API 参数](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)

## 4. API 设计

### 4.1 创建截图提取任务

```http
POST /api/chat-imports
X-Weiguang-User-ID: <user-id>
Content-Type: application/json
```

```json
{
  "attachment_ids": ["att-1", "att-2"],
  "source_type": "wechat_screenshot",
  "timezone": "Asia/Shanghai",
  "default_speaker": "unknown"
}
```

返回：

```json
{
  "import_id": "imp_xxx",
  "status": "processing"
}
```

### 4.2 查询提取结果

```http
GET /api/chat-imports/{import_id}
```

返回：

```json
{
  "import_id": "imp_xxx",
  "status": "needs_review",
  "messages": [
    {
      "id": "m-1",
      "speaker": "对方",
      "role_guess": "other",
      "text": "你最近还好吗？",
      "timestamp": "2026-08-25T20:15:00+08:00",
      "source_attachment_id": "att-1",
      "confidence": 0.96,
      "needs_review": false
    }
  ],
  "warnings": []
}
```

### 4.3 用户确认和修正

```http
PATCH /api/chat-imports/{import_id}
```

允许用户修改：

- 说话人名称和角色；
- 文本内容；
- 时间戳；
- 消息顺序；
- 删除不应导入的消息；
- 标记低置信度字段。

### 4.4 确认导入

```http
POST /api/chat-imports/{import_id}/confirm
```

请求：

```json
{
  "save_conversation": true,
  "extract_memories": false
}
```

第一版默认 `extract_memories=false`，用户需要在后续记忆审核页单独确认。

## 5. Qwen 提取提示词与结构化输出

服务端向 Qwen3.5-Flash 发送：

```json
{
  "role": "user",
  "content": [
    {
      "type": "text",
      "text": "请从这张聊天截图中提取可见对话。不要猜测被遮挡或看不清的文字；按从上到下顺序返回 JSON。识别失败的字段填 null，并给出 confidence。"
    },
    {
      "type": "image_url",
      "image_url": {"url": "<short-lived-oss-url>"}
    }
  ]
}
```

要求模型只输出结构化 JSON，字段包括：

```json
{
  "messages": [
    {
      "speaker": "左侧气泡",
      "role_guess": "user|other|unknown",
      "text": "消息内容",
      "timestamp_text": "20:15",
      "order": 1,
      "confidence": 0.0,
      "needs_review": false
    }
  ],
  "warnings": ["部分文字被遮挡"]
}
```

服务端必须再次用 Pydantic 校验模型输出，禁止直接把模型原始 JSON 写入数据库。

## 7.4 截图媒体占位符处理

截图识别到媒体气泡时，不尝试从截图恢复原始文件，而是在对应消息旁生成可操作的媒体占位卡片：

### 图片占位符

```text
[图片]
原始图片未上传
  [补充图片]  [忽略]
```

用户点击“补充图片”后：

1. 只允许选择图片文件；
2. 上传到当前用户的私有 OSS 路径；
3. 将附件绑定到当前导入批次和具体消息 ID；
4. 显示缩略图、文件名和上传状态；
5. 用户可以替换、移除或忽略该图片；
6. 用户确认导入后，消息保留图片引用，后续 Agent 需要理解该图片时再生成短期签名 URL。

### 视频占位符

```text
[视频 00:12]
原始视频未上传
  [补充视频]  [忽略]
```

用户点击“补充视频”后只接受视频文件，并将视频绑定到当前消息。视频的画面理解交给 `qwen3.5-flash`；如果用户需要理解视频音轨，另行提示使用支持音频输入的模型，不把 `qwen3.5-flash` 当作音频理解模型。

### 语音占位符

```text
[语音 00:18]
请先将这段语音转成文字，再填写转写内容
  [填写转写]  [暂不处理]
```

语音占位符默认不提供“上传后自动猜测”的流程：

1. 页面明确提示用户把音频转成文字；
2. 用户粘贴或填写转写文本；
3. 文本保存到该消息的 `transcript` 字段；
4. 来源标记为 `user_provided`，不伪装成模型高置信度识别；
5. 没有转写时保留 `[语音消息，原始音频未提供]`，不写入虚构内容。

### 绑定关系

媒体补充必须绑定到具体消息，而不是只绑定到导入批次：

```text
import_batch_id
message_id
media_id
media_kind: image | video
status: missing | uploading | uploaded | ignored
```

这样即使截图顺序被用户调整，图片/视频仍然跟随对应聊天消息，不会串到相邻消息。

### 对应接口

```http
POST /api/chat-imports/{import_id}/messages/{message_id}/media/presign
POST /api/chat-imports/{import_id}/messages/{message_id}/media/confirm
PATCH /api/chat-imports/{import_id}/messages/{message_id}/transcript
```

接口必须验证当前用户、导入批次归属和消息归属，禁止仅凭前端传来的消息 ID 写入附件。

## 8. 记忆提取边界

截图提取和 Agent 记忆提取必须分成两个步骤：

```text
截图 → 结构化对话记录 → 用户审核 → 候选记忆 → 用户确认 → Agent 可检索记忆
```

候选记忆类型：

- 用户偏好；
- 重要人物关系；
- 重要事件；
- 长期目标；
- 禁用话题；
- 用户明确要求记住的内容。

不得因为截图中出现一句话，就自动判断为长期事实。每条记忆需要保留来源消息和用户确认状态。

## 9. 安全、限制和成本

- 图片单张最大 10 MB；单次最多 10 张；
- OSS 对象私有，Qwen 只拿短期签名 URL；
- 提取任务超时、重试和幂等；
- 对同一截图哈希去重，避免重复调用视觉模型；
- 低置信度或文字遮挡时必须提示审核；
- 日志不记录原图、签名 URL或完整聊天文本；
- 用户可以删除导入批次及关联附件；
- 多张截图按顺序提交，但不假设截图之间一定连续；
- 视频不属于本方案，视频导入应复用多模态附件方案单独处理。

## 10. 实施阶段

### 阶段一：文本截图最小闭环

- 图片上传和导入任务；
- Qwen 结构化提取；
- 审核列表；
- 识别图片/视频/语音占位符；
- 图片/视频按消息补充上传或忽略；
- 语音消息显示“请先转文字”提示；
- 确认后写入 PostgreSQL；
- 只保存对话记录，不自动提取记忆。

### 阶段二：记忆审核

- 从已确认对话生成候选记忆；
- 用户逐条确认、修改、删除；
- Agent 运行时只注入已确认记忆。

### 阶段三：增强识别

- 多截图排序和重复消息去重；
- 时间戳归一化；
- 头像/昵称辅助说话人映射；
- 低置信度 OCR 的局部重试。

## 11. 验收标准

- 用户能上传聊天截图并看到处理进度；
- Qwen 能返回合法结构化消息 JSON；
- 文本顺序、说话人猜测和低置信度字段可审核；
- 用户确认前不写入正式聊天记录或长期记忆；
- 图片/视频可以绑定到正确的消息，语音没有用户转写时不生成虚构文本；
- 确认后记录能在当前用户会话中查看；
- 其他用户无法读取导入批次或 OSS 原图；
- 相同截图重复提交不会无限创建重复导入；
- Qwen 失败、格式错误、超时和签名 URL过期都有明确错误提示；
- 前端构建、后端迁移、图片上传、Qwen 视觉提取和浏览器审核流程通过。
