# [未完成] 首页全息卡轮播接入方案

> **状态**：未完成 (Pending)，mock 展示已实现；用户视觉验收及完整接入待完成
> **创建时间**：2026-09-09

## 当前依据

- 首页 `frontend/src/views/LandingView.vue` 的 healing-section 展示 12 条硬编码故事，两组循环共 24 个卡片节点；`frontend/src/assets/styles/landing.css` 用 55 秒 CSS 动画横向滚动，悬停暂停。
- 实验源文件为 `marketing_assets/2026-09-08/holo-card-experiment/three/App.vue`；dist 是构建产物。可复用圆角卡体、镭射 Shader、透明人物、浮动标签与资源释放逻辑。
- 实验依赖 Three.js 0.180.0，主 frontend 尚未声明 Three.js。当前只有一套人物素材，多种配色不能当作多个不同角色。

## 建议效果与交互

- 将当前横向评价卡区域改为竖向全息卡展廊，保留所在位置、黑底和两侧渐隐；桌面约三张，移动端一张为主并露出下一张。
- 卡面展示人物、短标题与一句寄语；长故事留在卡下 HTML 中，保证可读性。若继续使用现有硬编码故事，应标注示例，不将它们包装为已核实用户评价。
- 缓慢横向轮播，悬停、键盘聚焦或操作期间暂停；指针移动控制有限角度倾斜和镭射。手机横向滑动切卡、纵向仍滚动页面，不直接继承实验页 touch-action:none。
- 首页不显示实验导航和材质滑块。首版复用星辉素材，明确为同一作品的材质演示，新增不同角色需独立素材。

## 最小接入范围

1. 新增 `frontend/src/components/HoloStoryCarousel.vue`，提取实验卡片渲染并封装轮播；按需拆一个局部卡体构建函数，不引入通用引擎。
2. 一个透明 Canvas 与一个 WebGLRenderer 覆盖展示区域，按卡片 DOM 位置设置 viewport/scissor，仅绘制可见卡片；共享纹理和几何体。不可给 24 个循环节点分别创建渲染器。
3. 首页引用组件并调整该区域样式；正式素材进入 frontend 构建资产目录，frontend 添加与实验一致的 Three.js 依赖及需要的类型声明。不依赖本地 4173 服务或跨项目 dist 路径。
4. 组件接近视口时动态加载；离屏、页面隐藏时暂停，卸载释放资源；尊重 reduced-motion；WebGL 或素材失败时仍可见静态卡和文字。
5. 保留实验页，便于视觉对比。实施完成后同步 progress 两份文件，按实际验证状态更新本文。

## 官方依据与适用边界

- Three.js r180 官方多场景说明：https://github.com/mrdoob/three.js/blob/r180/manual/en/multiple-scenes.html 。采用共享 renderer 与可见区域裁剪，避免多 WebGL 上下文和重复资源。
- Vue 异步组件：https://vuejs.org/guide/components/async.html 。使用 defineAsyncComponent / dynamic import；本项目为客户端 Vite 应用，不套用 SSR lazy hydration 示例。
- 卡片造型、轮播速度、主题适配和悬停交互为本项目定制。实际性能需浏览器验收，现阶段不承诺帧率。
